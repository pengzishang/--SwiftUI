# 首页信息密度切换方案概览

## 已完成

- 新增完整增量 PRD，定义首页低／中／高三档信息密度。
- 将用户可见名称确定为「沉浸／标准／速览」，默认采用中密度「标准」。
- 明确三档共享“今日刊”品牌骨架，仅调整图片、摘要、互动指标、留白与单屏条目数。
- 定义首页快速入口与设置页入口、即时切换、本机持久化、浏览锚点保持和异常回落规则。
- 补充 P0/P1/P2、验收矩阵、指标体系、隐私要求、风险、待决问题和分阶段建议。

## 关键决策

1. 信息密度与列表字号相互独立；高密度不得依赖缩小字号。
2. 三档不改变内容源、顺序、日期分组和既有阅读操作。
3. 首版只覆盖日报首页，不做自由字段组合、跨页面复用或跨设备同步。
4. 当前缺少用户研究和行为基线，文档中的目标值均标注为待验证假设。

## UI 设计交付

- 已完成三档可交互原型，支持底部半屏选择、即时预览、自动保存与浏览锚点保持。
- 原型覆盖浅色／深色、iPhone 16 Pro 402pt 和 iPad 沉浸双列。
- 沉浸：16:9 大图或抽象版纹，标题、2 行摘要、完整指标。
- 标准：右侧 72pt 缩略图，标题、1 行摘要、紧凑指标。
- 速览：纯双行标题，不显示图片、摘要与指标。
- 已补充排版、间距、响应式、动效与 WCAG AA 无障碍规格。

## 下一步建议

- 先在交互原型中评审三档的信息层级、面板与 iPad 双列，再进入 SwiftUI 实现。
- 实现前确认 `List` 的首篇可见文章锚点能力，以及指标请求缓存策略。
- 使用真机验证 320–430pt、20–22pt 列表字号、AX3+、VoiceOver 与 Reduce Motion。
