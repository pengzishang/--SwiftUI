# v1.2 E2E UI 自动化测试设计分析报告

本报告针对《日报阅读器》App v1.2 版本的新增核心需求进行深入的项目结构与 UI 测试设计分析，并详细规划了涵盖 Tier 1 到 Tier 4 的黑盒 UI 自动化测试用例，同时起草了符合 `TEST_INFRA.md` 模板的内容。

---

## 一、 项目结构与现有测试体系分析

### 1. 现有项目结构与配置文件分析
- **`project.yml`**：项目通过 XcodeGen 维护。定义了三个 Target：
  - `DailyReader`：应用主 Target（iOS 17.0+，Swift 5.9）。
  - `DailyReaderTests`：单元测试 Target（已计划迁移到 Swift Testing）。
  - `DailyReaderUITests`：UI 自动化测试 Target（基于 XCTest，iOS 平台）。
- **`DailyReaderUITests/` 目录**：
  - 仅包含一个测试文件 `HomeFlowUITests.swift`。
  - 测试用例通过 `launchApp(scenario: String, resetCache: Bool)` 方法启动应用。此方法向 `XCUIApplication` 传递参数 `["-UITestMode"]`，并使用环境变量 `MOCK_SCENARIO` 控制 Mock 数据场景，确保测试不依赖外部网络环境。
- **`LocalFixtureDailyAPIClient.swift`**：
  - 核心 Mock 数据源处理器。它在应用处于 `UITestMode` 时被注入，读取 `MOCK_SCENARIO` 环境变量。
  - 目前仅实现了 `offline_no_cache`、`latest_empty`、`detail_empty_body`、`detail_missing_share`、`detail_long_body` 等与 v1.0/v1.1 首页和详情页相关的场景。

### 2. v1.2 版本核心变化与测试挑战
v1.2 版本引入了四大核心需求：
1. **Alamofire 迁移**：网络底层替换，注入特定的 User-Agent 头部以避开反爬。
2. **知乎热榜与回答列表**：引入热榜展示（Top 50，前三名高亮）、精选回答列表（前 20 条，带作者、赞同数）及 WebView 详情渲染。
3. **“我的”页面合并与胶囊滑块**：TabBar 调整为 4 个；合并“收藏”与“已读”为 `MeView`；顶部胶囊背景滑动动效（`.matchedGeometryEffect`）；统一搜索框。
4. **Keychain 备份与恢复**：防卸载数据丢失。在用户进行“已读/收藏/冷宫”操作时双写，且在沙盒空时从 Keychain 静默恢复。

**测试挑战与应对方案**：
- **WebView 渲染验证**：XCUITest 无法深入检查 WebView 渲染后的具体布局，但可以通过验证 `app.webViews.firstMatch` 的存在性以及静态文本是否存在来判断渲染成功。
- **胶囊滑块动画验证**：动画属于视觉和布局层面，黑盒测试将侧重于切换后子视图（`FavoritesView` 或 `ReadStoriesView`）是否发生改变，以及列表数据是否根据当前 Tab 进行正确的搜索过滤。
- **Keychain 备份与无缝恢复验证**：XCUITest 执行时，应用生命周期受 Runner 控制。我们可以通过启动参数 `-ResetUserDefaults` 来清除本地沙盒 `UserDefaults`，但不擦除 Keychain，然后启动应用，验证应用是否自动静默加载 Keychain 中的备份，并将 UI 状态（如已读置灰、收藏列表）无缝展现。

# TEST_INFRA.md - 自动化测试用例与基础设施设计 (v1.2)

本文件定义了《日报阅读器》v1.2 版本的 UI 自动化测试（XCUITest）基础设施规范、Mock 场景及四大测试层级的用例设计。用于指导 Worker 代理编写具体测试代码以及集成验收。

## 1. 测试基础设施与规范

### 1.1 运行与控制参数
UI 测试采用黑盒测试策略，通过向应用程序注入启动参数和环境变量来控制 Mock 数据和应用状态：
- **启动参数 `-UITestMode`**：使应用进入测试模式，注入本地 Fixture API 客户端。
- **启动参数 `-ResetCache`**：启动时强制清空本地 `DiskCacheStore` 和磁盘缓存。
- **启动参数 `-ResetUserDefaults`**：启动时强制清空本地沙盒 `UserDefaults`，但不擦除 Keychain，用于验证 Keychain 恢复机制。
- **环境变量 `MOCK_SCENARIO`**：指定 API 模拟的业务场景名称。

### 2.4 真实应用场景测试 (Tier 4)

#### T4-SCENARIO-01: 每日清晨阅读流 (Morning Reading Flow)
- **场景描述**：用户清晨起床有网时，启动 App 阅读今日日报和历史日报，并收藏感兴趣的内容。
- **步骤**：
  1. 启动 App，观察首页成功拉取今日最新日报。
  2. 左右滑动顶部轮播卡片，点击第二篇顶部故事进入详情页阅读。
  3. 阅读完毕，点击左上角返回按钮退回首页。
  4. 纵向向上滑动首页列表 2 次，触底加载昨天的历史日报。
  5. 点击历史日报中的一篇文章进入详情页，点击右上角操作按钮，在弹出的面板中选择“收藏”该文章。
  6. 点击返回退回到首页。
- **预期结果**：
  - 各个页面切换流畅，无卡顿闪退。
  - 详情页 HTML 渲染完整。
  - 最终收藏状态在本地和 Keychain 中均保存成功。

#### T4-SCENARIO-02: 热榜吃瓜与深读流 (Hot List Deep Reading Flow)
- **场景描述**：用户闲暇时进入热榜浏览全网热点，并深入阅读精选回答。
- **步骤**：
  1. 点击底部 TabBar 进入“热榜” Tab，成功拉取 Top 50 热榜列表。
  2. 观察到前三名标号高亮，滑动列表找到第 5 名的热榜项并点击。
  3. 进入该问题的回答列表页，观察到顶部正确展示问题标题，下方列表加载出前 20 条精选回答预览。
  4. 点击点赞数最高（如 5 万赞）的一条回答，进入回答详情页。
  5. 阅读通过 `HTMLWebView` 渲染的完整回答内容，向上滑动翻页。
  6. 阅读完毕，点击左上角返回，退回回答列表页；再次点击返回，退回热榜 Top 50 列表。
- **预期结果**：
  - 导航结构正确，能够层层返回。
  - 精选回答列表信息展示完整。
  - WebView 中回答正文渲染排版无误。

#### T4-SCENARIO-03: 统一管理个人收藏与历史 (Consolidated Profile Management Flow)
- **场景描述**：用户在“我的”页面管理自己的阅读历史和收藏，并通过搜索快速查找。
- **步骤**：
  1. 用户在此前已收藏了 3 篇文章，并阅读了 5 篇文章。
  2. 点击底部 TabBar 进入“我的” Tab，页面默认呈现“收藏”子 Tab 列表。
  3. 在搜索框中输入“SwiftUI”，列表中快速过滤出唯一一篇含有“SwiftUI”的收藏文章。
  4. 点击“已读”切换子 Tab，胶囊滑块平滑横向滑动。
  5. 此时搜索框中的内容自动过滤已读历史，列表中过滤显示出标题含有“SwiftUI”的已读历史文章。
  6. 点击其中一篇已读历史，进入详情页进行二次阅读。
- **预期结果**：
  - 胶囊滑块平滑切换，无突兀闪烁。
  - 搜索框在切换 Tab 时能对相应的子列表进行精准、实时的本地搜索过滤。

#### T4-SCENARIO-04: 地铁离线断网阅读流 (Subway Offline Reading Flow)
- **场景描述**：用户在地铁里断网，继续阅读已缓存的新闻，并尝试阅读未缓存内容。
- **步骤**：
  1. 用户在有网时启动应用，成功拉取了今日新闻和热榜数据。
  2. 断网（通过切换 Mock 场景为离线模式模拟）。
  3. 在首页执行下拉刷新，观察顶部出现离线 Banner，并提示“当前离线，正在显示缓存内容”。
  4. 点击此前已经阅读过（已标记已读）的一篇日报，能够秒开进入详情页（读取本地磁盘缓存渲染）。
  5. 返回首页，点击一篇未曾点击过且无本地缓存的新闻，页面跳转详情页，但显示网络不可用的中文错误页及重试按钮。
  6. 返回首页，切换到热榜 Tab，热榜展示先前加载的 Top 50 数据，点击其中一个回答项，因无缓存展示网络错误。
- **预期结果**：
  - 断网时应用表现稳定，离线提示语和 Banner 清晰易懂。
  - 有缓存的内容可正常秒开阅读；无缓存的内容展示重试和错误状态页，无白屏或崩溃。

#### T4-SCENARIO-05: 卸载重装静默恢复数据流 (App Re-installation Silent Recovery Flow)
- **场景描述**：用户因设备空间不足卸载了应用，重新安装后，之前的个人数据无缝恢复。
- **步骤**：
  1. 用户在前一次使用中，收藏了 2 篇文章，阅读了 5 篇文章，并将 1 篇首页文章移入冷宫。
  2. 模拟卸载重装：以 `-ResetUserDefaults` 启动参数启动应用（沙盒数据被完全重置为空，但系统 Keychain 仍保留先前备份）。
  3. 应用启动进入首页，在后台检测到沙盒为空，自动从 Keychain 读取备份数据进行反序列化，并重新初始化本地状态。
  4. 观察首页：被移入冷宫的那篇文章依然被过滤，未在首页普通列表中展示；已读的 5 篇文章标题呈现置灰状态。
  5. 点击进入“我的” Tab，在“收藏”列表中完整展示出先前收藏的 2 篇文章。
- **预期结果**：
  - 整个恢复过程完全静默，用户无任何弹窗或手工操作感知。
  - 本地 UserDefaults 成功恢复，UI 状态（已读置灰、冷宫过滤、收藏列表）与卸载前完全一致。
