# 知乎登录增量 PRD

- 文档状态：待评审
- 适用项目：知乎日报-SwiftUI
- 增量范围：仅新增知乎 OAuth2 登录与“我的”页账号区，不改变日报、热榜、设置及本地收藏/已读业务

## 1. 背景与目标

当前应用已有“日报 / 热榜 / 我的 / 设置”四个 Tab，“我的”页承载收藏、已读胶囊切换与统一搜索，但没有账号状态。

本增量目标：

1. 用户可从“我的”页发起知乎 OAuth2 授权，并在系统安全授权会话中跳转至知乎完成授权。
2. App 可接收授权回调，校验请求关联信息后完成会话建立，展示知乎昵称与头像。
3. 完整处理用户取消、拒绝授权、回调异常、网络失败、服务端失败和会话失效。
4. 登录会话在 App 重启后保持；用户可主动退出并清除本地认证材料。
5. 登录状态只影响“我的”页账号区，不影响其他 Tab，也不改变本地收藏、已读、冷宫数据及其 Keychain 恢复逻辑。
6. 沿用“暖纸、浓墨、宋体结构字、靛蓝交互色”的“今日刊”设计语言，并适配 iPhone 与 iPad 宽屏。
7. 交付可重复运行的 Unit Tests 与 UI Tests；UI Tests 通过 launch arguments / environment 注入认证 Mock，不依赖真实知乎授权页。

## 2. 非目标

1. 不新增 macOS 或 Mac Catalyst 目标；“桌面适配”仅指 iPad 横屏、分屏等宽屏尺寸。
2. 不实现账号注册、手机号/密码登录、第三方平台登录或多账号切换。
3. 不把收藏、已读、冷宫或设置同步至知乎账号，也不改变这些数据的现有本地归属。
4. 不因为登录状态改变日报、热榜、设置页的内容、权限或导航。
5. 不实现关注、私信、发布、点赞、知乎会员等知乎账号能力。
6. 不猜测、伪造或硬编码知乎 OAuth2 授权端点、换取 token 端点、用户信息端点、scope、回调规则或字段结构。
7. 不在 iOS 客户端保存、下发或使用 `client_secret`。
8. 不要求 UI 自动化测试访问真实知乎页面或使用真实账号、真实 token。

## 3. 用户故事

### US-1 发起登录

作为未登录用户，我希望在“我的”页看到清晰的知乎登录入口，以便通过知乎授权识别我的账号。

### US-2 完成授权

作为授权用户，我希望授权完成后返回 App，并在“我的”页看到昵称与头像，以确认登录成功。

### US-3 安全取消或拒绝

作为不愿继续授权的用户，我希望取消或拒绝后安全返回“我的”页，原有收藏与已读内容不受影响，并获得与结果相符的提示。

### US-4 失败后重试

作为遇到网络、回调或服务异常的用户，我希望看到可理解、可操作的错误信息，并能重新发起登录。

### US-5 会话保持

作为已登录用户，我希望关闭并重新打开 App 后仍保持登录，不需要重复授权。

### US-6 主动退出

作为已登录用户，我希望主动退出账号，确认后清除本地认证会话；本地收藏、已读和冷宫记录仍保留。

## 4. 需求优先级

### P0（本次必须）

1. “我的”页未登录、授权中、已登录、失败/失效状态及对应 UI。
2. 使用系统安全 Web 认证会话发起 OAuth2 授权；不得用内嵌 WebView 收集账号凭据。
3. 授权请求和回调关联校验；至少校验一次性 `state`，并防止回调重复消费。若平台支持或要求 PKCE，必须使用 PKCE。
4. 回调成功后通过已确认的真实契约换取会话并获取昵称、头像。
5. 用户取消、知乎拒绝、回调缺参/错参、`state` 不匹配、网络错误、服务端错误、资料获取失败的处理。
6. 会话安全保持：敏感 token 仅存 Keychain；不得写入 `UserDefaults`、日志、截图或错误文案。
7. 会话恢复与失效处理；启动时不得阻塞其他 Tab 使用。
8. 主动退出及确认；清除认证 token、临时授权上下文和内存账号资料，但保留现有业务数据。
9. iPhone 与 iPad 宽屏适配、深浅色和可访问性支持。
10. Unit Tests 与基于 Mock 注入的 UI Tests。
11. 未获得真实平台资料前，真实认证实现保持不可用/未配置状态，不拼接假 URL，不用网页首页代替授权端点。

### P1（建议同版本）

1. 头像加载失败时显示稳定占位符；昵称仍可展示。
2. 会话恢复期间显示轻量骨架/进度态，避免误显示“已退出”。
3. 对可恢复的网络错误提供“重试”，对配置缺失提供明确的开发/联调提示。
4. token 刷新：仅在平台已确认提供刷新机制时实现；刷新失败转为会话失效，不无限重试。
5. 登录成功、退出成功使用短暂且不打断操作的状态反馈。

### P2（后续评估）

1. 账号头像缓存策略优化。
2. 登录诊断信息页面；仅展示非敏感错误码与关联 ID。
3. 多环境认证配置管理（开发/预发/生产），前提是平台和 BFF 契约已建立。
4. 账号数据同步或更多知乎账号能力；必须另立 PRD，不属于本增量。

## 5. 完整状态与异常

### 5.1 状态模型

| 状态 | 进入条件 | “我的”页表现 | 可执行动作 |
|---|---|---|---|
| 未配置 | 缺少已确认的 client ID、回调或端点/BFF 配置 | 登录入口不可发起真实授权；显示“知乎登录暂不可用” | 开发环境可查看非敏感配置提示 |
| 未登录 | 无有效本地会话 | 登录卡：知乎标识文案、用途说明、“使用知乎登录”按钮 | 发起登录 |
| 准备授权 | 生成并保存一次性 `state`，按真实契约准备请求 | 按钮进入忙碌态，防重复点击 | 可取消当前流程 |
| 系统授权中 | 系统认证会话已展示 | App 内保持原页面；返回后按结果转移 | 在系统会话取消/继续 |
| 处理回调 | 收到 callback，正在校验并换取会话 | 进度文案“正在完成登录…”；禁止重复提交 | 等待；超时后重试 |
| 获取资料 | 已得到有效会话，正在获取昵称/头像 | 继续显示进度，不提前宣告成功 | 等待；失败后重试 |
| 已登录 | 会话有效且至少有稳定用户标识与昵称 | 账号卡展示头像、昵称和“退出登录” | 退出；必要时重试头像 |
| 恢复会话 | 冷启动读到本地安全会话并校验/取资料 | 轻量加载态；不阻塞其他 Tab | 等待；失败转未登录/失效 |
| 可重试失败 | 网络超时、临时服务错误、资料请求失败 | 就地错误说明与“重试登录”或“重试获取资料” | 重试、关闭提示 |
| 授权被拒绝 | 回调明确表示用户拒绝/平台拒绝授权 | 回到未登录卡，提示“未获得授权，未登录” | 再次登录 |
| 用户取消 | 用户关闭系统授权会话 | 回到未登录卡；不使用红色错误警告 | 再次登录 |
| 回调无效 | 缺少必要参数、回调 scheme/host/path 不符、`state` 不匹配、重复回调 | 中止流程，清理临时上下文，显示安全错误 | 重新登录 |
| 会话失效 | token 过期、撤销、鉴权失败，且无法按真实契约刷新 | 清除失效认证材料，保留业务数据；提示“登录已失效” | 重新登录 |
| 退出确认 | 已登录用户点击退出 | 确认框明确说明“收藏与已读不会删除” | 确认退出、取消 |
| 退出中 | 正在清除本地会话；若平台支持撤销则按契约处理 | 禁止重复点击，短暂进度态 | 等待 |

### 5.2 异常处理原则

1. **用户取消不等于错误**：不展示技术错误码，不改变业务数据。
2. **拒绝授权可解释**：明确“未获得授权”，不暗示账号或密码错误。
3. **回调安全优先**：`state` 不匹配、回调来源/格式不符合已注册规则、授权码重复使用时立即终止，不尝试容错换 token。
4. **仅成功一次**：一次登录事务只能消费一次回调；快速重复点击登录只保留一个活动事务。
5. **资料不完整**：无头像可用占位符；若缺少稳定用户标识或昵称则不进入完整已登录态，按真实接口契约归类为资料错误。
6. **断网/超时**：保留可重试入口，不清除仍被判定有效的既有会话；首次登录失败则回到未登录。
7. **服务端/BFF 错误**：展示通用文案和非敏感关联 ID（若有），不得显示 token、授权码、secret 或完整请求 URL。
8. **Keychain 错误/数据损坏**：认证模块安全降级为未登录并清除损坏的认证条目；不得误删现有收藏/已读 Keychain 条目。
9. **头像失败**：不导致退出；显示纸墨风格占位头像，可在下次进入或用户操作时重试。
10. **退出失败**：本地清除必须可完成；远端撤销若存在且失败，可提示“已在本机退出”，不得恢复本地 token。
11. **App 切后台/被终止**：未完成授权事务可在系统回调能力允许时继续；过期临时事务必须清理。已完成会话由 Keychain 恢复。

## 6. “我的”页 UI

### 6.1 信息架构

账号区新增在导航标题“我的”下方、现有“收藏 / 已读”胶囊切换栏上方。收藏/已读胶囊、搜索框和列表行为保持不变。

**未登录账号卡**

- 纸面浮层卡片，0.7pt 髮丝线，无阴影。
- 结构性标题使用宋体：“登录知乎账号”。
- 辅助文案使用系统字体：“授权后仅在此处显示昵称与头像，不会改变本地收藏和已读。”
- 主按钮使用靛蓝交互色，文案“使用知乎登录”。
- 未配置时按钮禁用，文案“知乎登录暂不可用”；不暴露配置细节给正式用户。

**授权中/恢复中**

- 在账号卡内显示系统进度指示和简短状态文案。
- 不遮挡收藏/已读内容，不使用全屏 Loading。
- 登录按钮禁用，避免并发授权。

**已登录账号卡**

- 展示圆形头像、昵称；头像为空或失败时使用“人”字/人物系统图标占位。
- 不展示 access token、用户 ID 等技术字段。
- “退出登录”为次级操作；点击后弹出确认框：“退出后将清除本机知乎登录状态，收藏和已读不会删除。”
- 退出操作使用常规墨/靛蓝交互表达，不把朱砂作为普通主按钮色；确认框可采用系统破坏性角色表达清除会话的语义。

**错误提示**

- 与账号卡就地关联，避免仅依赖短暂 Toast。
- 文案包含结果与下一步，例如“网络连接失败，请重试”。
- 技术详情只在 Debug/测试环境以非敏感形式提供。

### 6.2 视觉约束

1. 页面继续使用 `DS.paper`；卡片使用 `DS.paperElevated`；正文使用 `DS.ink` / `DS.inkSecondary`。
2. 靛蓝 `DS.indigo` 是登录、重试等交互强调色；朱砂不作为常规登录按钮色。
3. 宋体仅用于卡片标题、昵称等结构性文字；说明、状态、错误使用系统字体。
4. 深色模式使用既有动态色，不新增纯黑背景或阴影层级。
5. 不改变现有胶囊滑块的墨块反白和 `matchedGeometryEffect` 动效。

## 7. iPhone 与 iPad 适配

### iPhone

1. 账号卡占可用宽度，遵循现有 16pt 页面边距。
2. 头像、昵称、按钮在常规宽度可横向排列；窄屏或超大字体时允许纵向换行，不截断关键操作。
3. 授权由系统认证会话呈现，返回后仍停留“我的”页原滚动位置。

### iPad 宽屏

1. 不新增 macOS/Catalyst；仅支持 iOS/iPadOS target。
2. 账号区、胶囊和搜索框使用居中的可读内容列，避免在全屏横向无限拉伸；建议最大内容宽度约 720pt，最终以实现及可访问性测试为准。
3. 分屏、Slide Over、横竖屏尺寸变化时布局不重叠、不裁切，按钮仍可操作。
4. 系统认证会话可按系统行为以 sheet/presentation 展示，不自制桌面弹窗。

## 8. 可访问性

1. 登录按钮、重试、头像、昵称、退出按钮、错误提示均提供稳定的 accessibility label / identifier；UI Tests 不依赖坐标或视觉颜色。
2. 账号状态以文本和控件状态表达，不只依赖颜色、头像或进度动画。
3. Dynamic Type 下支持至少系统无障碍超大字号；卡片可增高、文本可换行，不遮挡收藏/已读切换。
4. VoiceOver 顺序：账号标题 → 状态/昵称 → 说明或错误 → 主操作；之后进入收藏/已读胶囊和搜索框。
5. 头像为装饰时隐藏；若需要表达身份，label 为“{昵称}的头像”，不得朗读图片 URL。
6. 进度态使用适当状态值（如“正在授权”“正在恢复登录”）；状态变化应可被辅助技术感知。
7. 可点击目标不小于 44×44pt；深浅色与高对比度模式下文字和描边可辨。
8. 尊重“减弱动态效果”；账号状态变化不依赖装饰性动画。

## 9. Mock 与真实能力边界

### 9.1 可在无开放平台应用时完成的 Mock 范围

1. 认证状态机、会话存储协议、账号模型和错误映射。
2. “我的”页全部状态与交互。
3. Unit Tests：状态转换、`state` 校验、重复回调、取消/拒绝/网络失败、会话恢复/失效、退出清理、Keychain 命名空间隔离。
4. UI Tests：通过 `-UITestMode` 及专用 launch arguments / environment 注入以下场景：
   - 未登录；
   - 授权成功（固定测试昵称与本地/测试头像）；
   - 用户取消；
   - 用户拒绝；
   - 回调无效；
   - 网络/服务失败后重试成功；
   - 已登录冷启动恢复；
   - 会话失效；
   - 头像失败；
   - 退出确认、取消退出、确认退出。
5. Mock 必须由认证依赖注入驱动，不启动真实系统授权页，不访问真实端点，不持有真实凭据。
6. Mock 参数只在 UI Test 构建/`-UITestMode` 下生效；正式运行忽略测试环境变量，避免测试后门。

建议测试参数语义（具体命名由技术设计确认）：`-UITestMode`、`-MockAuthScenario`、`-ResetAuthSession`；场景值只描述结果，不编码真实 URL 或 secret。

### 9.2 必须等待真实资料的边界

以下内容不得通过猜测完成：

1. 知乎开放平台当前是否接受新应用、产品是否具备 OAuth2 能力及审核条件。
2. authorization、token、userinfo、revoke 等端点及 HTTP 方法。
3. client ID 格式、允许的 redirect URI/scheme、scope、参数名、响应字段、错误码和 token 生命周期。
4. 是否支持/强制 PKCE、refresh token、token 撤销、Universal Link 或自定义 URL Scheme。
5. 用户资料授权范围是否包含昵称和头像。
6. 若 token 交换要求 `client_secret`，可信 BFF 的域名、接口契约、身份校验、限流、日志脱敏与部署环境。

在以上信息确认前，产品可验收 Mock 全流程，但不能宣称“真实知乎登录已联通”。

## 10. 安全与隐私要求

1. iOS 客户端不得包含 `client_secret`，包括源码、Info.plist、配置文件、构建参数、日志和测试夹具。
2. 若平台要求 secret，授权码必须交由可信后端/BFF 换 token；客户端仅调用已确认的 BFF 契约。
3. 使用一次性高熵 `state`；回调严格比对并及时销毁。若真实平台支持 PKCE，则使用安全随机 `code_verifier` 与对应 challenge。
4. token 仅进入专用 Keychain 条目；昵称与头像缓存按最小必要原则处理。认证 Keychain key 与现有收藏/已读 key 隔离。
5. 日志、埋点、崩溃报告不得记录授权码、token、secret、完整回调 URL 或可复用凭据。
6. 退出后清除本机认证材料；不删除与账号无关的收藏、已读、冷宫和阅读设置。
7. 回调 scheme/host/path 仅按开放平台登记值实现，拒绝非预期回调。

## 11. 验收标准

### 11.1 功能

- [ ] 未登录用户在“我的”页可识别登录用途并发起授权；收藏/已读功能继续可用。
- [ ] 点击登录只创建一个活动授权事务，并通过系统安全认证会话跳转。
- [ ] 合法回调经 `state` 等必要校验后完成会话建立，并显示真实接口返回的昵称和头像。
- [ ] 用户取消、拒绝授权、回调无效、网络失败、服务错误均回到可理解且可重试的状态，App 不崩溃。
- [ ] App 重启后可从 Keychain 恢复有效会话；恢复失败不阻塞日报、热榜、设置及本地“我的”内容。
- [ ] 会话过期/撤销后清除失效状态并提示重新登录。

## 12. 真实联调阻塞项

真实联调开始前必须由产品/开发方提供或确认：

1. 已申请并审核通过的知乎开放平台应用，以及允许本产品使用 OAuth2 的证明。
2. 官方、当前有效的 OAuth2 文档或平台控制台配置，不接受依据非公开日报 API 推断。
3. 正式/测试 client ID；client secret 只能配置在可信后端/BFF，不交付客户端仓库。
4. 已登记的 iOS 回调 URI、URL Scheme/Universal Link 规则及 App bundle ID 对应关系。
5. 授权、换 token、用户资料、刷新/撤销（如有）的真实端点、参数、scope、响应和错误码。
6. 昵称、头像所需 scope 已获批准，且隐私政策/用户告知满足平台要求。
7. PKCE、refresh token、token 生命周期与撤销策略的官方结论。
8. 若要求 client secret：可用的可信 BFF、TLS 域名、环境划分、接口契约、超时/重试、鉴权、限流、监控和脱敏方案。
9. 至少一个可用于联调的测试账号及授权撤销/重复授权验证方式；凭据不得写入仓库或自动化测试。
10. 真机回调、弱网、取消、拒绝、过期和退出的联调验收计划。

**阻塞结论：** 当前尚未申请知乎开放平台应用，因此只能完成产品设计、Mock 实现及自动化测试设计；真实授权跳转、token 交换和用户资料拉取均处于阻塞状态，不得以伪造端点或客户端 secret 绕过。

## 13. 关键产品决策

1. 登录是“我的”页的可选账号展示能力，不是使用 App、查看日报/热榜或管理本地收藏/已读的前置条件。
2. 登录与现有本地数据完全解耦；本期不进行合并、上传或跨设备同步。
3. 真实授权必须走系统安全认证会话；自动化测试走依赖注入 Mock，两者边界清晰。
4. 客户端永不持有 `client_secret`；平台若要求 secret，则必须由可信 BFF 完成 token 交换。
5. 没有官方配置就不构造端点；Mock 验收通过不等于真实 OAuth2 联调完成。
6. 宽屏仅覆盖 iPad，不扩展 macOS/Catalyst。
