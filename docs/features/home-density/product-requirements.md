# 首页信息密度切换产品需求文档

## 0. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品 | 日报阅读器（知乎日报 SwiftUI） |
| 文档类型 | 增量 PRD / 方案评审稿 |
| 功能名称 | 首页信息密度切换 |
| Project Name | `home_information_density` |
| 适用平台 | iOS 17+ |
| 影响范围 | 日报首页、首页展示偏好、相关埋点与测试 |
| 当前阶段 | 产品定义，不修改源码 |
| 默认推荐 | 中密度「标准」 |
| 上游规范 | `docs/design/design-system.md` |

**一句话定义：**允许用户在低、中、高三档首页信息密度之间切换，在不改变内容顺序和阅读能力的前提下，分别满足沉浸浏览、均衡阅读和快速扫描三类需求。

> 本方案中的“密度”不是简单调整字号。它由**单位屏幕内的信息条目数、单条内容字段、图片占比、留白和分隔节奏**共同决定；列表字号继续由现有“列表字体大小”独立控制。

---

## 1. 背景与问题

当前首页采用“日期刊头 + 文章列表”的统一结构。单条内容可同时展示标题、摘要或来源提示、互动数据和 `72pt` 缩略图，具有稳定的“今日刊”报刊气质，但只提供一种固定的信息组织方式。

不同阅读任务对首页的要求并不相同：

- 有些用户希望放慢速度，通过大图、摘要和留白感受内容，减少信息压迫。
- 有些用户需要标题、摘要、图片与指标之间的平衡，用较低决策成本选择文章。
- 有些用户只想在通勤或碎片时间快速扫过更多标题，尽快判断哪些值得打开。

仅靠现有“列表字体大小”无法解决上述差异：字号解决的是可读性，信息密度解决的是**单位视口展示什么、展示多少以及如何排列**。如果混为同一设置，高密度会牺牲可读性，低密度也可能沦为“字更大但信息结构没变”。

### 1.1 已知事实

- 首页存在日期刊头、文章标题、提示信息、互动数据、缩略图、已读状态、不感兴趣手势和历史分页。
- 项目设计语言强调暖纸、浓墨、宋体结构文字、髮丝线和日期刊头，不适合为每档密度引入互不相关的视觉皮肤。
- 用户已经可以在设置页调整列表字号，范围为 `14–22pt`。
- 当前没有用户访谈、行为基线或密度偏好分布数据，因此本文中的目标值属于**待验证假设**，不能作为已证实的用户结论。

### 1.2 不解决的成本

- 首页只能服务单一阅读节奏，用户需要通过更多滚动或更高认知负担完成选文。
- 直接在现有列表上继续叠加互动数据、AI 信息等字段，会造成默认首页越来越拥挤。
- 后续每次首页改版都可能争论“应该更丰富还是更简洁”，但缺少稳定的分层框架。

## 2. 产品判断与设计原则

### 2.1 核心判断

首页不应做成三套品牌风格，而应做成**同一份报纸的三种版式节奏**：

- **低密度「沉浸」：**内容预览更完整，一次少看几篇。
- **中密度「标准」：**信息和节奏平衡，作为默认档。
- **高密度「速览」：**突出标题扫描效率，一次多看几篇。

### 2.2 设计原则

1. **内容公平：**三档使用相同的数据源、排序、日期分组和分页规则，不因档位隐藏某篇文章。
2. **任务导向：**档位差异服务于选文效率，不追求纯视觉变化。
3. **即时可感知：**切换后当前首页应立即重排，用户无需刷新或重新进入。
4. **上下文稳定：**切换时尽可能保持当前浏览日期和锚点文章，避免跳回顶部。
5. **字号独立：**密度不覆盖用户的列表字号偏好，也不得用低于可读下限的字号换取“高密度”。
6. **品牌一致：**三档共享纸底、墨色、日期刊头、髮丝线、已读状态和交互语义。
7. **无障碍优先：**系统大字号下允许布局自适应变松，不能为了维持“每屏篇数”而截断关键内容或缩小触控区。

## 3. 目标与成功定义

### 3.1 用户目标

1. 用户能根据当前阅读任务，在 2 次操作内切换首页信息密度。
2. 切换后无需重新学习操作方式，文章打开、已读、不感兴趣、刷新和分页行为保持一致。
3. 高密度提高标题扫描效率，低密度提供更充分的选文上下文。
4. 用户的选择在后续启动中保持稳定，并可随时恢复默认设置。

### 3.2 产品目标

1. 建立可扩展的首页信息层级，降低未来新增字段对默认首页的拥挤压力。
2. 通过真实行为数据验证三类首页节奏是否存在稳定需求。
3. 在不降低文章打开质量和阅读完成度的前提下，提高首页选文效率。

### 3.3 非目标（Non-goals）

- **不改变推荐或排序算法。**密度只改变展示，不改变内容供给，避免将版式效果与推荐效果混淆。
- **不提供任意拖拽或逐项自定义。**首版不支持用户分别开关图片、摘要、指标等，防止组合爆炸和测试成本失控。
- **不将字号并入密度档位。**列表字号继续作为独立的可访问性与阅读偏好设置。
- **不为三档设计三套配色或品牌主题。**三档统一遵循“今日刊”设计系统。
- **不扩展至热榜、收藏、冷宫、已读等页面。**首版仅验证日报首页；其他列表后续根据数据决定是否复用。
- **不新增服务端账号同步。**首版按本机偏好持久化，不承诺跨设备同步。
- **不以提高点击率作为唯一目标。**更高点击率可能来自误点或标题党，需要结合阅读完成、快速返回等质量指标判断。

## 4. 用户与使用场景

### 4.1 核心场景

| 场景 | 用户任务 | 推荐档位 | 价值 |
| --- | --- | --- | --- |
| 周末或晚间慢读 | 希望充分了解文章后再进入 | 低密度「沉浸」 | 大图与摘要提供更完整上下文 |
| 日常阅读 | 在信息量与浏览节奏之间平衡 | 中密度「标准」 | 保留主要判断信息，滚动成本适中 |
| 通勤或碎片时间 | 快速扫过当天和历史标题 | 高密度「速览」 | 单屏更多条目，降低翻页和滚动成本 |
| 视力或认知辅助 | 使用大字号、VoiceOver 等 | 任意档位，自适应布局 | 保留偏好名称，但优先保证可读与可操作 |

### 4.2 用户故事

1. **作为碎片时间阅读者，我希望首页一次展示更多标题，以便快速找到值得阅读的内容。**
2. **作为偏好沉浸浏览的读者，我希望看到更大的配图和更完整的摘要，以便在打开文章前理解其主题。**
3. **作为日常读者，我希望使用信息量均衡的默认布局，以便不配置也能顺畅阅读。**
4. **作为会在不同场景阅读的用户，我希望快速切换密度并立即预览结果，以便随时调整阅读节奏。**
5. **作为返回应用的用户，我希望应用记住上次选择，以便无需重复设置。**
6. **作为使用大字号或辅助功能的用户，我希望密度设置不牺牲文字可读性和触控区域，以便完整使用首页。**
7. **作为正在浏览历史日报的用户，我希望切换密度后仍停留在当前日期和附近文章，以便不丢失浏览上下文。**

## 5. 三档信息密度定义

### 5.1 档位命名

面向用户使用“体验名称 + 密度说明”，避免单独的“高／中／低”让用户误解价值高低：

| 内部枚举建议 | 用户名称 | 辅助说明 |
| --- | --- | --- |
| `low` | 沉浸 | 低密度 · 大图与完整预览 |
| `medium` | 标准 | 中密度 · 信息均衡 |
| `high` | 速览 | 高密度 · 更多标题 |

### 5.2 档位对比

| 维度 | 低密度「沉浸」 | 中密度「标准」 | 高密度「速览」 |
| --- | --- | --- | --- |
| 核心任务 | 深入预览后选文 | 日常均衡选文 | 快速扫描标题 |
| 默认状态 | 否 | **是** | 否 |
| 条目形态 | 图文纵向卡片感，但保持报刊髮丝线 | 当前左右图文结构的优化版 | 紧凑标题列表 |
| 标题 | 最多 3 行 | 最多 3 行 | 最多 2 行 |
| 提示／摘要 | 最多 2 行 | 最多 1 行 | 默认不展示；无图且有关键来源时可保留 1 行来源标签，需设计确认 |
| 互动指标 | 展示完整可用指标 | 展示紧凑指标 | 首版不展示 |
| 图片 | 有图时使用宽幅图；无图不占位 | 有图时 `72pt` 左右缩略图 | 默认不展示缩略图 |
| 条目垂直留白 | 16–20pt | 8–12pt | 5–8pt |
| 分隔 | 髮丝线 + 更明显段落节奏 | 标准髮丝线 | 连续髮丝线，强调扫描基线 |
| 日期刊头 | 完整日期、星期、篇数、文武线 | 完整日期、星期、篇数、文武线 | 保留完整语义，压缩上下留白，不缩小到不可读 |
| 预期单屏条目数* | 约 2–3 篇 | 约 4–5 篇 | 约 7–9 篇 |

\* 以约 `390pt` 宽、默认列表字号和常见标题长度估算，仅用于设计目标；最终需通过真机样本测量，不能写死为验收条件。

### 5.3 低密度「沉浸」

**信息优先级：**题图 > 标题 > 摘要／来源 > 互动指标。

建议结构：

```text
日期刊头 + 文武线

[可选宽幅题图]
文章标题，最多 3 行
摘要或来源，最多 2 行
互动数据

髮丝线
```

规则：

- 有有效图片时展示宽幅图片，建议比例接近 `16:9`，实际高度需在视觉设计阶段确定。
- 无图时从标题开始，不展示“日”字大占位图，不保留媒体空白。
- 保留更完整的提示信息与互动数据，帮助用户在进入详情前做判断。
- 不使用悬浮卡片阴影；通过纸面色、留白和髮丝线建立层次。
- 已读态继续使用淡墨标题和图片透明度，不改变条目占用空间，防止列表跳动。

### 5.4 中密度「标准」

**信息优先级：**标题 > 缩略图 > 摘要／来源 > 互动指标。

建议沿用并收敛当前首页结构：

```text
日期刊头 + 文武线

文章标题，最多 3 行             [72pt 缩略图]
摘要或来源，最多 1 行
紧凑互动数据

髮丝线
```

规则：

- 作为新用户和未设置用户的默认档。
- 尽量保持当前首页的视觉与行为连续性，降低改版学习成本。
- 无图时图片槽完全折叠，文字区域使用可用宽度；不得展示无意义占位图来维持结构。
- 互动数据异步加载前后不得造成明显行高跳动；实现阶段需要在“预留稳定高度”与“无数据不占位”之间验证。

### 5.5 高密度「速览」

**信息优先级：**标题 > 已读状态 > 必要来源；图片和互动指标让位于扫描效率。

建议结构：

```text
紧凑日期刊头 + 文武线
文章标题，最多 2 行
髮丝线
文章标题，最多 2 行
髮丝线
……
```

规则：

- 首版默认隐藏图片和互动指标，避免视觉焦点横向跳动。
- 标题不得缩小到用户设置字号以下；密度主要通过减少辅助字段和收紧留白实现。
- 标题仍应允许最多 2 行，禁止强制单行造成大量语义截断。
- 已读状态必须清晰可辨，但不能仅依赖颜色；VoiceOver 应读出“已读／未读”。视觉是否增加轻量符号由设计阶段确认。
- 滑动“不感兴趣”、点击进入、下拉刷新和历史分页能力与其他档完全一致。

## 6. 切换入口与交互规则

### 6.1 入口策略

采用“**首页快速入口 + 设置页持久入口**”的双入口：

1. **首页快速入口（P0）：**导航栏右上角提供“首页布局”菜单，包含沉浸、标准、速览三项，当前项带勾选状态。
2. **设置页入口（P0）：**在“阅读设置”中增加“首页信息密度”，进入后选择三档并查看简短说明。

首页入口服务于高频场景切换，设置页入口保证可发现、可解释和可恢复。具体图标需避免与现有 AI“知”按钮争抢空间，可优先评估合并为工具菜单，而不是无限增加独立 Bar Item。

### 6.2 切换行为

- 用户选择档位后，首页在当前页面立即重排，不触发网络刷新。
- 切换应保持当前日期分节与首个可见文章作为锚点；允许因行高变化产生小幅位移，但不得直接跳到列表顶部。
- 如果用户在设置页修改，返回首页后使用新档位；若首页仍在导航栈中，可实时更新。
- 选择结果本机持久化，应用重启后继续生效。
- 首次安装、偏好值缺失或存储值非法时，回落到中密度「标准」。
- 不提供自动随时间、横竖屏或网络状态切换档位，避免界面自行变化导致困惑。
- 切换动效使用系统默认布局过渡；开启 Reduce Motion 时取消缩放和大幅位移，仅保留即时重排或淡入淡出。

### 6.3 字号与密度的关系

- 密度选择和现有“列表字体大小”是两个独立偏好。
- 调整密度不得重置字号；调整字号也不得改变已选密度。
- 在较大动态字号或 `listFontSize = 20–22pt` 时，高密度允许自然展示更少条目，这是可访问性的正确结果，不视为功能失败。
- 在极端字号下，如横向空间不足，图片应优先移到标题下方或隐藏辅助内容，不得压缩触控区、裁切全文入口或产生横向滚动。

## 7. 功能需求与优先级

### 7.1 P0 — Must have

#### A. 档位模型与默认值

- 系统必须支持 `low`、`medium`、`high` 三种稳定值。
- 默认值必须为 `medium`；未知值必须安全回落为 `medium`。
- 档位仅影响首页展示，不影响数据获取、排序、已读、隐藏、收藏或详情页行为。

#### B. 三档布局

- 三档必须按第 5 节定义调整图片、辅助字段、指标、行数和留白。
- 所有档位必须完整展示文章标题和文章入口；不得因密度选择漏掉条目。
- 图片、摘要或互动数据缺失时，对应区域必须折叠，不保留无意义空白。
- 日期分组、当日印章和文武线在三档中必须保留。

#### C. 切换与持久化

- 首页必须提供可访问的快速切换入口，设置页必须提供带解释的持久入口。
- 切换必须立即生效，不刷新接口，不清空已加载历史内容。
- 切换后必须尽量保持当前可见文章锚点。
- 用户选择必须在本机持久化并跨启动生效。

#### D. 既有能力一致性

- 三档均必须支持文章进入、已读状态、不感兴趣、下拉刷新、离线提示、加载／失败／空态和历史分页。
- 三档的文章顺序和总数必须一致。
- 切换期间不得重复发起文章指标请求或历史分页请求。

#### E. 可访问性

- 所有可点击区域不得小于 `44×44pt`。
- VoiceOver 必须读出档位名称、密度说明、当前选中状态，以及文章已读状态。
- 三档必须支持浅色、深色、高对比度、Dynamic Type 和 Reduce Motion。
- 密度不得通过小于用户设置字号的文字实现。

### 7.2 P1 — Should have

- 切换菜单中提供简化的版式示意缩略图，帮助用户在选择前理解差异。
- 首次进入密度设置时展示一次性说明：“信息密度不会改变推荐内容和字体大小”。
- 对切换前后的可见文章锚点进行更精确恢复，减少长列表中的位置漂移。
- 埋点区分入口来源（首页／设置）、切换前后档位和是否最终保持，不记录文章标题等内容数据。
- 为不同屏宽、字号、图片有无、摘要有无、指标状态建立截图回归测试。

### 7.3 P2 — Future considerations

- 用户分别自定义“显示图片／显示摘要／显示互动数据”。只有三档无法覆盖真实需求且数据足够明确时再开放。
- 根据设备宽度为 iPad 设计专属多栏版式，但仍复用同一档位语义。
- 将密度偏好复用到收藏、已读、热榜等列表页面。
- 支持 iCloud 或账号级跨设备同步。
- 基于使用场景给出档位建议，但不得未经用户确认自动切换。

## 8. 状态与边界

| 状态／边界 | 预期行为 |
| --- | --- |
| 首次安装 | 使用中密度「标准」 |
| 偏好值非法或迁移失败 | 回落到「标准」，首页保持可用 |
| 列表加载中 | 使用当前档位的骨架节奏；切换档位不重新请求 |
| 空态／错误态 | 不因密度改变核心文案和操作，只允许间距适配 |
| 离线缓存 | 可切换已加载内容的版式，不依赖网络 |
| 无图片 | 折叠图片区域，禁止保留大块占位 |
| 无提示或摘要 | 折叠辅助文本，不显示空行 |
| 无互动指标 | 折叠指标行；不得永久显示加载状态 |
| 指标延迟返回 | 只在允许展示指标的档位更新；不得导致明显滚动跳动 |
| 1–4 行长标题 | 按各档上限截断；VoiceOver 仍读取完整标题 |
| 中英混排／Emoji | 保持正常换行，不产生横向滚动 |
| 320pt 窄屏 | 优先保证标题和触控；中密度图片可缩小或下移，具体由设计稿确定 |
| iPad 分栏 | 使用当前栏宽自适应，不直接套用全屏 iPad 固定尺寸 |
| 字号 20–22pt／AX3+ | 允许密度自然降低，不强求目标单屏条目数 |
| 快速连续切换 | 最终状态与最后一次选择一致，无崩溃、重复加载或状态错乱 |
| 切换时正在加载历史 | 加载继续；已加载和新到达条目均使用最终档位 |
| 切换时有滑动操作展开 | 收起滑动操作后重排，避免操作按钮错位 |

## 9. 验收标准

### 9.1 功能验收

1. **默认值：**清除首页密度偏好后启动，首页使用中密度「标准」；写入未知值后仍安全回落到标准。
2. **档位可辨识：**使用同一组至少 10 篇混合样本，三档在图片、辅助字段、指标和留白上符合第 5 节定义，肉眼可明确区分，而非仅字号不同。
3. **内容一致：**三档展示的文章 ID、顺序、日期分组和篇数完全一致。
4. **即时切换：**首页切换后无需刷新即可完成重排；接口请求记录中不新增首页刷新请求。
5. **位置保持：**滚动至历史日期并切换，切换后原首个可见文章仍在视口内或相邻一个条目范围内，不跳回顶部。
6. **持久化：**选择任意档位，杀进程并重新启动后仍保持该档位。
7. **双入口一致：**首页和设置页显示相同当前值；任一入口修改后，另一入口状态同步。
8. **字段缺失：**无图、无摘要、无指标样本均不出现对应空槽；文章仍可正常进入。
9. **既有能力：**三档均能完成文章进入、已读更新、不感兴趣、下拉刷新、离线提示、错误重试和历史加载。
10. **请求稳定：**在三档间连续切换 10 次，不额外触发历史分页，不重复创建同一文章的并发指标请求。
11. **快速切换：**连续点击三个档位后，最终 UI、勾选状态和持久化值均与最后一次选择一致。
12. **状态页面：**加载、空态、失败和离线状态下切换不崩溃，内容加载完成后使用最终档位。

### 9.2 视觉与无障碍验收

13. **品牌一致：**三档均保留“今日刊”的纸底、墨色、日期刊头、文武线和髮丝线，不使用通用卡片阴影。
14. **字号独立：**先将列表字号分别设为 `14/16/18/20/22pt`，再切换三档，字号值不被修改。
15. **窄屏适配：**在 `320/375/390/430pt` 宽度下无横向滚动，标题和导航操作可用。
16. **大字号：**在 Dynamic Type 100%/150%/200% 与 AX3+ 下，文字可读、文章可进入、切换可操作；高密度条目数减少不判失败。
17. **VoiceOver：**可读出完整文章标题、已读状态、档位名称、说明和选中状态；视觉截断不截断辅助功能文本。
18. **触控与动效：**所有入口和行操作热区不小于 `44×44pt`；Reduce Motion 下无缩放和大幅位移动画。
19. **主题：**浅色、深色和高对比度下，文字、分隔线、已读态和选中态均可辨识。
20. **稳定性：**切换、旋转、分栏变化、字号变化和指标回填后，无明显内容闪烁、行重叠或列表位置失控。

### 9.3 建议样本矩阵

| 维度 | 必测值 |
| --- | --- |
| 密度 | 沉浸／标准／速览 |
| 图片 | 有图、无图、加载失败、超宽图、竖图 |
| 标题 | 1/2/3/4 行；中文、英文、中英混排、Emoji |
| 辅助信息 | 有摘要、仅来源、无提示 |
| 指标 | 加载中、有值、部分值、无值、失败 |
| 状态 | 未读、已读、不感兴趣操作展开 |
| 屏宽 | 320、375、390、430pt、iPad 分栏 |
| 字号 | 列表 14/16/18/20/22pt；Dynamic Type 100%/150%/200%/AX3+ |
| 外观 | 浅色、深色、高对比度 |
| 动效 | 标准、Reduce Motion |
| 网络 | 正常、缓慢、离线缓存、失败重试 |

## 10. 指标体系与实验假设

> 当前缺少基线数据。上线前必须先补齐基线，以下目标值用于形成可验证假设，不应包装成已确认承诺。

### 10.1 北极星观察指标

**有效选文率：**从首页打开文章后，达到“有效阅读”阈值的会话占首页文章打开会话的比例。

“有效阅读”建议定义为满足任一条件：

- 详情页停留达到约 30 秒；或
- 阅读进度达到 25%；或
- 完成收藏、分享等高意图行为。

最终阈值需结合现有埋点能力和真实阅读时长分布确认。

### 10.2 驱动指标

| 指标 | 目的 | 建议观察方式 |
| --- | --- | --- |
| 密度功能发现率 | 用户是否看见入口 | 进入过密度菜单的首页活跃用户占比 |
| 密度切换率 | 是否存在实际需求 | 至少切换一次的首页活跃用户占比 |
| 7 日保持率 | 档位是否持续有价值 | 切换后 7 日仍保持非默认档的用户占比 |
| 首次有效打开耗时 | 选文是否更高效 | 进入首页至首篇有效阅读的中位时长 |
| 每 100 次滚动的有效打开数 | 扫描效率 | 按档位分组比较 |
| 首页浏览深度 | 用户覆盖内容范围 | 每次首页会话看过的唯一文章数／日期数 |

### 10.3 健康指标

| 指标 | 风险信号 |
| --- | --- |
| 打开后 5 秒内返回率 | 高密度可能带来误选；低密度可能预览不足或标题误导 |
| 详情有效阅读率 | 点击上升但阅读质量下降 |
| 首页卡顿率／掉帧 | 低密度大图或频繁重排引入性能问题 |
| 图片流量与加载失败率 | 沉浸档大图增加流量成本 |
| VoiceOver 与大字号任务完成率 | 密度设计破坏可访问性 |
| 设置后短时反复切换率 | 档位差异不清楚或结果不符合预期 |

### 10.4 首轮目标建议

在补齐至少 14 天基线后设定正式目标。首轮可用以下门槛做灰度判断：

- 上线 30 天内，密度菜单发现率达到 20% 以上。
- 尝试切换的用户中，30% 以上在 7 天后仍使用非默认档，说明不是一次性好奇。
- 任一档位的有效选文率不低于上线前基线 3 个百分点以上。
- 打开后 5 秒内返回率相对基线恶化不超过 2 个百分点。
- 首页性能指标、崩溃率和无障碍关键任务无显著回归。

这些阈值需由产品与数据根据当前 DAU、样本量和埋点成熟度共同校准。

### 10.5 隐私原则

- 仅记录匿名档位值、入口来源、切换事件和聚合行为结果。
- 不在密度埋点中上传文章标题、摘要、正文或用户输入。
- 偏好默认保存在本机；如未来跨设备同步，应明确告知并遵循《个人信息保护法》及适用隐私要求。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 三档差异只剩“大小不同” | 用户不理解价值，切换率低 | 用字段、图片、留白和条目数共同定义档位；设计评审必须同屏对比 |
| 高密度牺牲可读性 | 误点、疲劳、无障碍回归 | 不缩小用户字号；保留 2 行标题和 44pt 触控；大字号自适应变松 |
| 低密度大图增加流量与卡顿 | 首页首屏变慢 | 复用缓存、按目标尺寸请求、延迟加载；建立性能健康指标 |
| 切换导致列表跳位 | 用户丢失上下文 | 以首个可见文章 ID 作为锚点恢复，而非只保存像素偏移 |
| 指标异步回填引发行高跳动 | 浏览位置漂移 | 明确稳定高度策略或仅在数据就绪后渐显；真机验证 |
| 设置项过多 | 增加决策负担 | 默认标准档；名称场景化；只提供三档，不开放首版自由组合 |
| 导航栏入口拥挤 | 与 AI 入口冲突 | 优先合并工具菜单；视觉设计阶段评估主次和可发现性 |
| 三套布局维护成本上升 | 回归范围扩大 | 共享数据与交互容器，以配置驱动字段和间距，避免复制三份业务逻辑 |
| 指标被点击率误导 | 鼓励误选或标题党 | 使用有效选文率与 5 秒返回率联合判断 |

## 12. 待决问题

### 12.1 阻断设计的问题

1. **[产品／设计] 低密度题图形态：**使用全宽 `16:9`、固定高度裁切，还是根据原图比例设上限？建议优先固定比例以保证滚动稳定。
2. **[产品／设计] 高密度是否保留来源：**首版建议默认只展示标题；若真实样本中大量标题缺乏语境，可保留一行来源标签。
3. **[产品／设计] 首页快速入口承载：**独立布局按钮、与 AI 入口并列，还是合并为工具菜单？建议合并工具菜单，避免导航栏堆叠。
4. **[设计] 已读态的非颜色提示：**是否需要轻量符号，还是由 VoiceOver 语义补充即可？需结合视觉噪音评估。
5. **[工程] 切换后的锚点恢复能力：**SwiftUI `List` 当前能否稳定获取首个可见文章 ID；若不能，是否需要调整容器方案？

### 12.2 不阻断产品定义的问题

6. **[数据] 当前是否已有首页曝光、滚动深度、详情停留和阅读进度埋点？**若缺失，首版需先补基线事件。
7. **[工程] 互动指标请求是否按可见行触发并可复用缓存？**需避免切换引发重复请求。
8. **[设计／工程] 中密度无图时是否保持纯文字满宽，还是使用小型报刊占位符？**本 PRD 默认纯文字满宽。
9. **[产品] 是否需要首轮灰度开关？**建议有，以便快速回退并控制样本。
10. **[用户研究] 三种任务是否真实覆盖主要用户？**建议在开发前用 5–8 名用户进行概念测试，不得把本文的场景假设当成用户证言。

## 13. 建议交付阶段

### Phase 0 — 样本与基线

- 选取至少 30 篇真实首页样本，覆盖长短标题、有无图、有无提示和指标状态。
- 补齐或确认首页曝光、打开、有效阅读、快速返回、滚动深度和性能基线。
- 对 5–8 名用户开展三档概念测试，重点验证命名、差异感知和默认选择。

### Phase 1 — 视觉原型

- 使用同一组真实文章制作三档高保真对照稿。
- 覆盖 `390pt` 默认字号、`320pt` 窄屏、`22pt` 列表字号和 AX3+。
- 先验证信息层级和单屏条目数，再确定动画与入口图标。

### Phase 2 — MVP 实现

- 完成三档布局、双入口、即时切换、本机持久化、默认回落和既有能力回归。
- 完成可访问性、截图矩阵和请求稳定性验证。
- 通过灰度开关向小流量开放。

### Phase 3 — 数据评估

- 观察至少 30 天，比较档位保持、有效选文率、快速返回率、性能和无障碍反馈。
- 决定是否扩展到其他列表页，或是否需要有限的字段自定义。

## 14. 发布门槛

以下条件同时满足方可全量上线：

- P0 验收项全部通过，三档内容顺序和既有操作无回归。
- 使用同一真实样本完成三档视觉评审，差异明确且保持“今日刊”品牌一致性。
- `320–430pt`、iPad 分栏、列表字号 `14–22pt`、Dynamic Type 200%／AX3+、VoiceOver、深浅色和 Reduce Motion 完成专项验证。
- 切换不触发首页刷新、重复分页或重复指标并发请求；列表锚点恢复达到验收要求。
- 已建立上线前基线、灰度开关和核心／健康指标看板。
- 隐私检查确认不采集文章内容和不必要的个人信息。

## 15. 本轮产品结论

1. **默认采用中密度「标准」**，延续当前首页，降低迁移成本。
2. **三档共享同一品牌与业务骨架**，差异集中在图片、辅助字段、互动指标、留白和单屏条目数。
3. **高密度不靠缩小字号实现**，而是隐藏低优先级字段并收紧版式；低密度也不是简单放大，而是增加内容预览。
4. **首页快速入口与设置页入口同时保留**，兼顾场景切换与设置可发现性。
5. **切换必须即时、持久并保持浏览锚点**，且不得触发网络刷新。
6. **首版不做自由组合和跨页面扩展**，先用三档验证需求，再根据真实数据决定下一步。
