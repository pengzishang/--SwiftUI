# 文章详情双正文系统增量 PRD

## 0. 项目信息

| 项目 | 内容 |
| --- | --- |
| 产品 | 日报阅读器（知乎日报 SwiftUI） |
| 文档类型 | 增量 PRD |
| Project Name | `article_detail_dual_style` |
| Language | 中文 |
| Programming Language | Swift + SwiftUI + WebKit（`WKWebView`） |
| 适用平台 | iOS 17+ |
| 上游设计 | `docs/design/article-navigation/dual-system-plan.md` |
| 变更范围 | 文章详情页的模板分流、导航反馈与共享阅读能力 |

**原始需求复述：**文章详情分为两种风格：问答式沿用“问答长卷”，采用单一可滚动 `WKWebView` 与普通滚动导航标题；“标题 + 正文”的文章式采用“墨迹岛”，标题离开视口后出现标题胶囊与朱砂阅读进度，点击后展开完整标题和作者。两类页面共享无边框 Bar Item、“纸面压印”按钮语言、操作菜单、头像条件渲染、图片浏览器、安全链接、阅读进度与位置恢复、返回顶部，以及深浅色、动态字号、Reduce Motion 适配。

---

## 1. 增量范围与产品目标

### 1.1 本次范围

本 PRD 仅定义文章详情页双正文系统的增量需求，不重复定义首页、热榜、收藏、已读等既有功能，也不要求在本文档阶段修改源码。

### 1.2 产品目标

1. **准确呈现内容结构：**将问答合集与连续文章映射到合适的阅读模板；无法可靠识别时必须安全回落，不因误判阻断阅读。
2. **提升长文定位效率：**文章式在标题滚出后通过“墨迹岛”持续提供标题上下文与阅读进度；两类正文均支持进度、位置恢复和返回顶部。
3. **统一且可访问的交互体验：**两种模板共享导航、菜单、图片、链接、按钮反馈和无障碍规范，并在深浅色、200% 字号与 Reduce Motion 下保持可用。

### 1.3 非目标

- 不改写、重排或摘要原始文章内容。
- 不在原生层重复渲染正文题图、完整标题、作者或正文。
- 不新增评论发布、账号关注后端、离线全文下载等业务。
- 不以标题是否包含“瞎扯”作为模板判断的唯一条件。

## 2. 用户故事

1. **As a 问答合集读者, I want 问题与多个回答在一条连续长卷中自然滚动, so that 我能保持上下文并顺序阅读。**
2. **As a 长文读者, I want 标题离开视口后看到标题胶囊与阅读进度, so that 我能随时确认当前文章和阅读位置。**
3. **As a 返回阅读的用户, I want 再次打开文章时恢复上次位置, so that 我无需重新寻找中断点。**
4. **As a 需要查看媒体或外链的用户, I want 安全地放大正文图片并打开链接, so that 我能扩展阅读而不承担未知跳转风险。**
5. **As a 使用大字号、深色模式、VoiceOver 或 Reduce Motion 的用户, I want 两种模板都遵循系统辅助设置, so that 我能舒适、完整地阅读和操作。**

## 3. Requirements Pool

### 3.1 P0 — Must have

#### A. 模板识别与回落

- 系统**必须**支持 `qa`、`article`、`fallback` 三种展示状态。
- 有显式模板字段时**必须**优先使用显式字段；无字段时才进行 DOM 结构识别。
- DOM 同时呈现重复的“问题 → 回答”、多个问题节点或多个回答/作者组合时，应判为 `qa`；具备标题与连续段落且无明显问答重复结构时，应判为 `article`。
- 无法可靠识别、字段非法或 DOM 检测失败时，**必须**进入 `fallback`，使用普通连续正文与普通导航标题。
- 模板识别失败不得导致白屏、内容缺失或循环重载。

#### B. 单一正文滚动容器

- 两种模板及 `fallback` **必须**使用单一可滚动 `WKWebView` 承载全部正文。
- 外层不得再以 SwiftUI `ScrollView` 包裹禁用滚动的 WebView。
- 原生层不得重复插入题图、标题、作者；正文图片必须遵循 HTML 原始顺序。
- 图片延迟加载、字号变化或旋转后不得出现固定最小高度造成的大段假空白。

#### C. 问答式“问答长卷”

- Web 内完整标题、问题、回答作者、回答正文及图片应连续排列。
- 标题底边离开导航栏下沿后，导航中央**必须**显示普通单行标题副本；标题重新进入视口后隐藏。
- 问答式不得显示“墨迹岛”或导航栏常驻朱砂进度。
- 页面作者头像、回答作者头像有有效资源时保留；无头像时折叠槽位；头像加载失败且有作者名时可使用首字回退。

#### D. 文章式“墨迹岛”

- Web 内必须保留完整标题、作者区域及连续正文；题图按数据条件渲染，无题图时不保留媒体占位高度。
- 当 Web 标题底边离开导航栏下沿后，导航中央**必须**出现“墨迹岛”；标题重新进入视口后退出。
- “墨迹岛”必须包含：单行截断标题、左侧朱砂阅读进度标记；不得自动跑马灯或持续闪动。
- 点击“墨迹岛”必须在导航栏下展开完整标题、作者名/来源、已阅读百分比；仅在头像有效时展示作者头像。
- 点击空白、再次点击“墨迹岛”或继续滚动后，展开面板必须收起。
- AX3 及以上字号时，胶囊可将可见文案降级为“文章标题”，但 VoiceOver 标签必须保留完整标题。

#### E. 共享导航与操作

- 返回与操作 Bar Item **必须**采用无边框视觉，左右槽等宽，点击热区不小于 `44×44pt`。
- 可点击控件必须遵循“纸面压印”语言：默认无通用投影；按下以靛蓝纸面底色与尺度反馈表达状态。
- Reduce Motion 开启时必须取消缩放和位移动效，保留颜色、显隐和语义反馈。
- 两类正文必须共享同一操作菜单及顺序：分享、收藏/取消收藏、设为已读/未读、分隔线、不感兴趣/恢复到日报。
- 收藏采用乐观更新；不感兴趣执行后提供撤销入口，不弹出低价值确认框。

#### F. 共享阅读能力

- 阅读进度、标题可见性和返回顶部状态必须直接基于 `WKWebView.scrollView` 或 DOM 哨兵计算。
- 阅读进度必须限制在 `0%–100%`；内容高度小于等于可视高度时按 `100%` 处理，不得除零或显示负值。
- 系统必须按文章唯一标识保存阅读位置；再次进入且内容可滚动时恢复到最近有效位置。
- 位置恢复值超出新内容范围时必须截断到有效区间；用户主动返回顶部后应更新已保存位置。
- 返回顶部操作必须可用，并在 Reduce Motion 下使用无大幅位移的系统兼容方式完成。

#### G. 图片与链接安全

- 点击正文图片必须进入全屏图片浏览器，支持双击缩放、拖拽、单击关闭；长按提供保存、复制、分享。
- 图片浏览器的 VoiceOver 必须读取图片 `alt`；缺失时读取“正文图片，第 N 张”。
- 站内链接必须走 App 内 `NavigationStack`；外部 `http(s)` 链接必须进入安全浏览器。
- 未知或不允许的 scheme 必须拒绝打开，并提供用户可理解的反馈。

#### H. 适配与可访问性

- 两种模板必须支持浅色、深色、高对比度、100%/150%/200% 动态字号。
- VoiceOver 必须可读取完整标题、作者、图片替代文本、链接语义、菜单状态和阅读百分比。
- 关键文字在 320pt 宽屏与 200% 字号下不得被不可恢复地裁切；正文必须仍可滚动和操作。

### 3.2 P1 — Should have

- 模板识别应记录识别来源（显式字段/DOM/回落）与失败原因，便于灰度验证，不记录正文敏感内容。
- “墨迹岛”进入建议使用约 220ms 的轻动效，退出约 165ms；进度变化应平滑收敛且不阻塞滚动。
- 问答式返回顶部按钮可附带当前阅读百分比，但不得与导航标题争抢中央空间。
- 图片加载失败应保留可理解的替代文本或失败提示，且不破坏正文段落顺序。
- 阅读位置恢复应在 DOM 与延迟图片布局稳定后校准，避免首次恢复后明显二次跳动。
- 应为模板、标题行数、头像、媒体、字号、屏幕、外观、动效、网络与链接类型建立自动化测试矩阵。

### 3.3 P2 — Nice to have

- 支持文章式首段首字下沉，但仅在内容结构可靠且大字号下不影响可读性时启用。
- 支持对图片图注、作者身份和预计阅读时长做更完整的语义标注。
- 支持按真实样本误判率优化 DOM 识别规则或由服务端逐步补齐显式模板字段。
- 支持跨设备同步阅读位置；本增量仅要求本机持久化。

## 4. UI 设计草案

### 4.1 共享骨架

```text
原生导航栏
├── 左：无边框返回 Bar Item（固定槽）
├── 中：普通标题 / 墨迹岛（弹性槽）
└── 右：无边框操作 Bar Item（固定槽）

单一可滚动 WKWebView

按需覆盖层
├── 墨迹岛完整标题面板（仅 article）
├── 全屏图片浏览器
├── 安全浏览器
└── 返回顶部入口
```

### 4.2 模板差异

| 能力 | 问答式 `qa` | 文章式 `article` | `fallback` |
| --- | --- | --- | --- |
| 正文结构 | 问题与回答连续长卷 | 标题、作者、可选题图、连续正文 | 普通连续正文 |
| 标题滚出后 | 普通导航标题 | 墨迹岛标题胶囊 | 普通导航标题 |
| 导航阅读进度 | 不常驻；可在返回顶部入口显示 | 朱砂纵向进度 | 不常驻 |
| 点击中央标题 | 无展开要求 | 展开完整标题、作者、进度 | 无展开要求 |
| 头像 | 页面/回答作者按有效性展示 | 作者按有效性展示 | 按已有有效数据展示 |

## 5. 状态和边界

### 5.1 核心状态

| 状态 | 触发 | 产品表现 | 退出条件 |
| --- | --- | --- | --- |
| 加载中 | 进入详情，正文尚未就绪 | 保留导航返回能力；显示既有加载反馈 | HTML 成功或失败 |
| `qa` 阅读 | 显式字段或 DOM 判为问答 | 问答长卷；标题滚出后显示普通导航标题 | 离开页面或重新加载 |
| `article` 标题可见 | 文章式且标题仍在视口 | 不显示墨迹岛 | 标题底边越过导航栏下沿 |
| `article` 墨迹岛收起 | 文章式且标题离开视口 | 显示胶囊、朱砂进度和截断标题 | 点击胶囊、标题重新进入或离开页面 |
| `article` 墨迹岛展开 | 点击胶囊 | 展示完整标题、可选头像、作者/来源、进度 | 点击空白、再次点击、继续滚动或标题重新进入 |
| `fallback` 阅读 | 无法可靠识别 | 普通连续正文与普通导航标题 | 离开页面或重新加载 |
| 子资源失败 | 图片/头像失败 | 折叠头像或展示图片替代信息；正文继续可读 | 资源重试成功或离开页面 |
| 正文失败 | 主文档无法加载 | 展示明确错误与重试；导航仍可返回 | 重试成功或离开页面 |

### 5.2 边界规则

- **标题：**覆盖 1、2、4 行及中文、英文、混排；空标题时中央标题区域保持空，不显示无意义胶囊。
- **作者：**无作者时折叠作者行；有作者无头像时不保留头像空槽；头像失败不得反复闪烁或撑开布局。
- **题图：**无题图时文章式直接衔接分隔线与正文；题图失败时不得留下固定大空白。
- **短文：**不可滚动内容的阅读进度为 100%，不展示无意义的返回顶部入口；文章标题未离开视口时不显示墨迹岛。
- **内容变化：**动态字号、旋转、分栏宽度变化或图片延迟加载后，应重新校准标题哨兵、最大滚动距离和进度。
- **快速滚动：**滚动期间不得频繁切换模板；墨迹岛展开面板收到有效滚动即收起。
- **重复进入：**位置恢复仅在同一文章标识上生效；文章内容显著缩短时恢复点截断到当前最大偏移。
- **网络：**离线缓存正文可照常阅读；无缓存且主文档失败时展示重试，不应误显示旧文章内容。
- **链接：**空 URL、畸形 URL、`javascript:`、`file:` 等非允许 scheme 均不得直接执行。
- **可访问性：**VoiceOver 聚焦展开面板时，收起后焦点应回到墨迹岛或合理的导航元素。

## 6. 验收标准

### 6.1 功能验收

1. **模板分流：**准备 `qa`、`article`、`fallback` 各不少于 10 篇代表性样本；显式字段样本 100% 按字段展示，DOM 无法判断样本 100% 回落且可完整阅读。
2. **问答长卷：**问答样本中问题、回答、作者与图片按 HTML 顺序连续展示；无重复题图、标题或作者；全程不出现墨迹岛。
3. **普通导航标题：**问答式和 `fallback` 的 Web 标题底边离开导航栏下沿后显示普通导航标题，反向滚回后隐藏；往返 10 次无明显闪烁。
4. **墨迹岛交接：**文章式 1/2/4 行标题在标题离开视口后均显示墨迹岛，标题重新进入后隐藏；触发点不依赖固定标题高度。
5. **墨迹岛内容：**收起态可见截断标题和 `0%–100%` 朱砂进度；点击后完整标题可读，作者/来源与进度正确，无有效头像时头像槽完全折叠。
6. **展开收起：**空白点击、再次点击、继续滚动三种操作均可收起面板；收起后正文滚动不受阻塞。
7. **单滚动容器：**长文、短文和延迟图片样本均只有一个正文滚动手势响应区域；页面底部无固定 `520pt` 类假空白，无外层与 WebView 滚动冲突。
8. **阅读恢复：**同一篇可滚动文章滚动至约 30%、退出并重新进入后，恢复进度与退出前误差不超过 ±5 个百分点；内容高度变化后恢复位置仍在有效范围。
9. **返回顶部：**在长文任意位置触发后可到达顶部，最终进度回到起始状态；短文不出现无意义入口。
10. **操作菜单：**两种模板菜单项、顺序及状态一致；收藏乐观更新失败时可回滚并反馈；不感兴趣后可撤销。
11. **图片浏览器：**正文图片点击可全屏打开，双击、拖拽、单击关闭与长按菜单均可执行；图片顺序及 VoiceOver 文案正确。
12. **链接安全：**站内、外部 `http(s)`、未知 scheme 三组用例分别进入站内导航、安全浏览器和拒绝反馈；未知 scheme 不触发系统跳转。

### 6.2 视觉与无障碍验收

13. **按钮一致性：**返回、操作菜单及正文可点击控件无通用投影，点击热区均不小于 `44×44pt`，按下状态具有纸面压印反馈。
14. **主题与字号：**`qa/article/fallback` 在浅色、深色、高对比度及 100%/150%/200% 字号下正文可读、控件可操作；320/390/430pt 与 iPad 分栏无横向正文滚动。
15. **Reduce Motion：**开启后墨迹岛及按钮不发生缩放或位移，仍有清晰的显隐、颜色与进度反馈。
16. **VoiceOver：**可依次读取完整标题、作者、阅读百分比、图片替代文本、链接和菜单状态；AX3 以上即使胶囊显示“文章标题”，其无障碍标签仍为完整标题。
17. **稳定性：**快速上下滚动、动态字号切换、横竖屏/分栏变化及图片加载完成后，标题交接与进度在 1 秒内校准，无崩溃、白屏或模板切换。

### 6.3 建议测试矩阵

| 维度 | 必测值 |
| --- | --- |
| 模板 | `qa` / `article` / `fallback` |
| 标题 | 空、1/2/4 行；中/英/混排 |
| 作者 | 有头像、无头像、头像失败、无作者 |
| 媒体 | 无图、题图、单图、连续多图、图片失败 |
| 字号 | 100%、150%、200%、AX3+ |
| 屏幕 | 320、375、390、430pt、iPad 分栏 |
| 外观 | 浅色、深色、高对比度 |
| 动效 | 标准、Reduce Motion |
| 网络 | 正常、缓慢、离线缓存、主文档失败、子资源失败 |
| 链接 | 站内、外部 `http(s)`、空/畸形 URL、未知 scheme |

## 7. 待确认事项

1. **显式模板字段来源：**现有知乎日报接口无法提供时，是在本地适配层维护映射，还是仅依赖 DOM 识别？字段的最终命名与兼容策略需由架构确认。
2. **DOM 判定阈值：**“两个及以上问题节点”“多个回答/作者组合”的权重与冲突处理，需要用真实文章样本集确认目标误判率。
3. **阅读位置持久化周期：**每次滚动节流保存、页面退出保存，还是两者结合；本地记录的数量上限与清理策略待确认。
4. **返回顶部入口形态：**问答式是否正式显示进度百分比；文章式是否复用相同入口，需视觉稿最终确认。
5. **墨迹岛展开层交互：**展开层是纯信息面板还是允许点击作者进入来源页；当前 P0 按纯信息面板验收。
6. **关注按钮：**上游设计包含关注视觉，但当前是否具备真实关注能力未明确；若无后端能力，应隐藏而不是提供无效按钮。
7. **图片长按能力：**“复制”复制图片本身还是图片 URL；保存到相册时的权限拒绝提示文案需确认。
8. **安全浏览器实现：**采用 `SFSafariViewController` 还是现有 App 内浏览器，以及站内域名白名单范围需确认。
9. **恢复语义：**用户读到接近末尾后再次打开，是恢复原位置还是直接从顶部开始；当前默认仍恢复最近位置。
10. **灰度与指标：**是否需要对模板识别来源、fallback 比例、墨迹岛展开率、位置恢复成功率建立埋点与灰度开关，需结合项目隐私与发布计划确认。

## 8. 发布门槛

以下条件同时满足方可替换现有文章详情实现：

- P0 验收项全部通过，无阻断阅读的已知缺陷。
- 三类模板均有真实样本与 fixture 覆盖，且 `fallback` 可安全阅读。
- 位置恢复、收藏、分享、已读/未读、不感兴趣等既有能力无回归。
- 200% 字号、深色模式、Reduce Motion 与 VoiceOver 完成专项验收。
- 未知 scheme 被拒绝，站外链接不绕过安全浏览器。
