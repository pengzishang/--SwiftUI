# DailyReader 文章互动数据 UI 设计规范

## 结论

采用“**题下注脚**”方案：数据是阅读判断的辅助信息，不是社交反馈主角。

- 首页列表：只展示 **知乎日报热度** 与 **知乎日报评论数**。
- 文章正文：按来源分为“日报数据”和“原回答”两行。
- 不展示浏览量、平台分享次数；当前没有可靠且语义准确的数据源。
- 异步加载不阻塞标题、图片或正文；无数据、失败、无法映射时整组隐藏。
- 不做磁盘缓存或跨页面缓存，但允许在单次页面生命周期内合并重复的并发请求。

---

## 1. 信息架构

### 1.1 首页文章 Cell

推荐顺序：

```text
文章标题
来源提示

[热度图标] 30 热度   [评论图标] 10 评论                72pt 缩略图
```

显示字段：

1. `dailyPopularity` → “30 热度”
2. `dailyCommentCount` → “10 评论”

规则：

- `popularity` 只能命名为“热度”，不能写成“点赞”“赞同”或“推荐数”。
- 首页不请求、也不显示原回答赞同/收藏，避免一行文章触发两级网络请求。
- 原 `hint` 保留优先位置，并与指标保持独立层级。
- 指标固定独占一行，不与 `hint`、来源或其他元数据横向拼接。
- 两项指标可在指标行内并排展示；宽度不足时自然换行，不压缩缩略图。
- 不使用圆角胶囊、彩色徽章、卡片底色或大号数字。

### 1.2 文章正文头部

推荐位置：标题与现有来源/日期行之后、`RuleLine()` 之前。

```text
完整文章标题
知乎日报 · 七月二十九日

日报数据  热度 30 · 评论 10
原回答    赞同 1,848 · 评论 179 · 收藏 1,050

文武线
正文
```

来源规则：

- “日报数据”仅承载 `story-extra` 字段。
- “原回答”仅在映射为单个、有效 Zhihu answer 时显示。
- 多原回答合集不做求和，不制造虚假的“文章总赞同”。
- `thanks_count` 暂不进入默认界面：优先级低，且会使头部过密；后续若需要，可放入可展开的“更多数据”。

## 2. 视觉规格

### 首页

| 属性 | 规格 |
|---|---|
| 指标字体 | 系统字体 11pt，Regular |
| 数字 | `monospacedDigit()` / tabular numerals |
| 颜色 | `DS.inkSecondary` |
| 图标 | SF Symbols 11–12pt，Regular |
| 图标建议 | 热度：`chart.bar.xaxis`；评论：`bubble.left` |
| 图标与数字 | 3pt（使用自定义 `HStack`，不采用 `Label` 默认间距） |
| 指标之间 | 9pt |
| 标题与 `hint` | 10pt |
| `hint` 与指标行 | 8pt |
| 无 `hint` 时标题与指标行 | 14pt |
| 背景/边框 | 无 |

首页指标必须比标题、缩略图和 `hint` 弱一个视觉层级。

### 正文

| 属性 | 规格 |
|---|---|
| 来源标签 | 宋体 Bold 12pt，`DS.ink` |
| 数据文字 | 系统字体 12pt，`DS.inkSecondary` |
| 数字 | `monospacedDigit()` |
| 数据组上距 | 12pt |
| 组内上下内边距 | 10pt / 11pt |
| 两行间距 | 7pt |
| 分隔 | 数据组顶部 0.7pt `DS.hairline`；底部沿用现有 `RuleLine()`，不重复画线 |
| 文武线上距 | 由现有标题区 `VStack` 间距控制 |

不使用 `DS.indigo` 强调数字，因为指标为只读信息，不是交互入口。朱砂、赭石、藤黄均不用于指标。

### 深色模式

直接使用现有动态令牌：

- 纸底：`DS.paper`
- 标签：`DS.ink`
- 数值：`DS.inkSecondary`
- 分隔：`DS.hairline`

不增加发光、半透明玻璃或额外阴影。

## 3. 异步状态

### Idle / Loading

- 标题、摘要、缩略图、正文按原逻辑立即渲染。
- 指标区域不显示 `ProgressView`，不显示骨架，不显示“正在加载数据”。
- 不为每个 Cell 预留固定高度，避免首页出现一排无意义的灰条。

### Loaded

- 先过滤有效字段，再一次性提交 UI。
- 使用 140ms `opacity` 淡入，可附带最多 2pt 的轻微位移。
- Reduce Motion 开启时直接出现，不做位移。
- 不逐个数字 stagger，避免列表持续闪动。

### Partial

- 只显示真实存在的字段。
- 不使用“—”“未知”“暂无”填位。
- 正文中若日报数据可用、原回答不可用，只显示“日报数据”一行。

### Empty / Failure

- 整个指标组件返回 `EmptyView`。
- 不显示行内错误、重试按钮或 Toast。
- 数据失败不能改变文章正文加载状态。
- 重新进入页面或手动刷新文章时自然重试。

## 4. 布局稳定性

用户要求“无数据则隐藏”，因此无法同时保证绝对零位移与零占位。推荐取舍：

1. **首页优先不占位**：指标加载后，Cell 可能增加一行，但只对可见区域产生轻微重排。
2. 指标始终位于独立行，以稳定的信息层级换取略高的 Cell 高度，不与 `hint` 争抢水平空间。
3. 图片始终保持 72×72pt，不因数据出现而缩放。
4. 同一 Cell 的请求只提交一次最终可见状态，避免字段分批回来导致多次跳动。
5. 正文指标放在正文开始前；即使高度增加，也不会打断已开始阅读的中段内容。

不建议为“避免跳动”永久预留空白，因为它与“没有则隐藏”的产品意图冲突，也会让失败状态留下不自然空洞。

## 5. 数字格式

### 首页紧凑格式

- `0...9_999`：原数显示，例如 `1,848`
- `10_000...999_999`：一位小数，例如 `1.2 万`
- `>= 1_000_000`：一位小数，例如 `128.4 万`

### 正文精确格式

默认使用本地化千分位：`12,480`。若数字超过 7 位导致换行过密，可降级为紧凑格式。

### 零值

- 接口明确返回 `0`：属于有效数据，可以显示“0 评论”。
- 字段缺失、解码失败、来源不可用：隐藏该字段。
- 如果一组中所有字段都不可用，隐藏整组。

## 6. 可访问性

### VoiceOver

首页每组指标合并为一个元素：

```text
“知乎日报热度 30，评论 10”
```

正文按来源分别合并：

```text
“日报数据，热度 30，评论 10”
“原回答，赞同 1848，评论 179，收藏 1050”
```

- 图标设为装饰，不单独聚焦。
- 动态结果插入时不抢 VoiceOver 焦点，也不设置逐 Cell 的主动播报。
- 用户聚焦 Cell 或指标组时读取最新值。

### Dynamic Type

- 指标字体应使用可缩放的语义样式或 `UIFontMetrics` 缩放。
- AX 大字号时，首页 `hint` 与指标允许换行；不把指标压成不可读的小字。
- 正文来源标签保持行首，数据换到下一行；不固定整组高度。
- 200% 字号下仍需保持每项语义完整，不能只剩图标。

### 对比度

`DS.inkSecondary` 在 `DS.paper` 上必须持续满足 WCAG AA 的正常文本对比要求；若实测不足，应为 11–12pt 指标单独增加一个更深的 `metricSecondary` 语义令牌，而不是改为彩色。

## 7. 请求生命周期与“不缓存”边界

“不缓存”定义为：

- 不落盘。
- 不写入 SwiftData。
- 不跨页面生命周期保留。
- 重新进入文章时重新请求最新数据。

允许但不等同于缓存：

- 同一页面生命周期内，按 story ID 合并并发请求。
- 同一个可见 Cell 不重复启动相同 Task。
- Cell 离屏或被复用时取消未完成请求。

推荐请求策略：

1. 首页 Cell 进入可见区域后仅请求 `/story-extra/{id}`。
2. 快速滚动时取消离屏任务，并限制并发数。
3. 正文页独立请求 story-extra。
4. 原回答指标仅在正文详情 HTML 已加载、且解析到唯一有效 answer ID 后请求。
5. 文章正文加载与指标加载使用独立 phase；指标失败不得覆盖正文错误或 banner。

## 8. 后续 SwiftUI 组件边界（仅设计建议）

```swift
struct ArticleMetricsSnapshot: Equatable {
    let dailyPopularity: Int?
    let dailyCommentCount: Int?
    let originalAnswer: OriginalAnswerMetrics?
}

struct OriginalAnswerMetrics: Equatable {
    let voteupCount: Int?
    let commentCount: Int?
    let favoriteListCount: Int?
}

enum ArticleMetricsPhase: Equatable {
    case idle
    case loading
    case loaded(ArticleMetricsSnapshot)
    case unavailable
}
```

视图建议：

```text
StoryMetricLine       // 首页，只接收日报指标
ArticleMetricByline   // 正文，按来源分组
MetricValueLabel      // 图标、标签、格式化数字
ArticleMetricsLoader  // 生命周期与取消，不承担视觉
```

插入点：

- `StoryRowView.swift`：现有 `hint` 下方的独立指标行；无 `hint` 时直接位于标题下方并使用更大的上距。
- `ArticleDetailView.swift`：`metaLine` 之后、`RuleLine()` 之前。

该方案已在 `feature/article-metrics-ui` 分支按真实运行界面完成试做：保留现有列表与详情核心布局，仅增补题下指标信息；实现结果以 SwiftUI 源码和运行截图为准。
