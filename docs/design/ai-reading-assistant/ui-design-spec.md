# DailyReader AI 文章问答与多 Session UI 设计规格

**文档类型**：低保真产品界面与交互规格  
**适用版本**：AI 文章问答第一阶段  
**目标平台**：iOS / iPadOS 为主，并定义跨尺寸自适应规则  
**设计基线**：现有「今日刊」纸墨设计系统  
**可访问性目标**：WCAG 2.1 AA、iOS VoiceOver、动态字体 200% 适配

---

## 1. 设计依据与当前实现核验

### 1.1 当前工程编译状态

- `xcodegen generate` 已成功完成，项目文件可正常生成。
- 当前 `xcodebuild` 在 **Resolve Package Graph** 阶段被 Xcode 27 Beta 的嵌套沙盒限制阻断：`sandbox-exec: sandbox_apply: Operation not permitted`。
- 阻断发生在 Alamofire `Package.swift` 依赖解析阶段，尚未进入本项目 Swift 源码编译。因此，本设计以已读取的现有 SwiftUI 实现与 `docs/design/design-system.md` 为可靠基线，不将此次命令视为“项目已编译通过”。

### 1.2 已核验的现有界面基线

| 页面/组件 | 当前结构 | 可复用设计模式 |
|---|---|---|
| `HomeView` | `NavigationStack > List > Section > StoryRowView`，大标题导航，纯纸底列表 | 首页 AI 入口放入右上角工具栏，不新增一级 Tab |
| `ArticleDetailView` | 导航栏 + 外层 `ScrollView` + 封面/题头/指标/HTML 正文 + 右下角阅读进度按钮 | AI 悬浮按钮与阅读进度按钮组成垂直控件组；AI 对话使用全屏覆盖 |
| `HTMLWebView` | 不可滚动 `WKWebView` 嵌入外层 SwiftUI 滚动，已有图片点击 JS bridge | 扩展正文选择、AI 编辑菜单与选区回传，不改变文章滚动架构 |
| `MeView` | 自定义书房刊头 + 阅读档案 + 胶囊切换 + 搜索 + 内容列表 | 沿用纸面浮层、44pt 触控区、`ViewThatFits` 适配模式 |
| `SettingsView` | 纸底 `List`，阅读设置/管理/关于分组 | 新增“AI 服务”分组与独立配置页入口 |
| 状态组件 | `LoadingView`、`ErrorStateView`、`OfflineBanner` | AI 状态统一沿用淡墨、朱砂、纸面浮层和髮丝线，不引入通用发光/渐变 UI |

### 1.3 用户、场景与品牌方向

- **目标用户**：日常阅读知乎日报、希望就当前文章即时理解、查证和追问的个人用户。
- **核心任务**：不中断阅读位置地询问 AI；管理多个长期 Session；清楚知道回答使用了哪篇文章、哪个模型以及是否真的执行了搜索。
- **使用情境**：手机上的碎片阅读与专注长读；iPad 横屏阅读；弱网、离线或 Endpoint 不稳定场景。
- **品牌气质**：克制、可信、编辑感。AI 是“刊物旁的批注助手”，不是另一个喧闹产品。
- **视觉记忆点**：暖纸、浓墨、蓝黑靛色、宋体结构文字、文武线；不用渐变、毛玻璃和无意义阴影。

### 1.4 设计原则

1. **阅读优先**：正文位置、选择状态和阅读节奏不应被 AI 功能破坏。
2. **上下文可见**：用户始终知道当前 Session 是否绑定文章、绑定哪篇、是否经过压缩。
3. **会话稳定**：切换 Session 不静默替换文章上下文，不允许消息串写。
4. **真实可追溯**：只有 Endpoint 返回搜索状态或来源时才展示“已搜索”和引用。
5. **原生优先**：手机沿用导航、Sheet、编辑菜单、键盘和触觉反馈等 iOS 习惯。
6. **状态先于装饰**：加载、取消、失败、未配置和上下文冲突必须比视觉点缀更清楚。

## 2. 全局信息架构

```text
AppRootView
├── 日报 Tab / NavigationStack
│   ├── HomeView
│   │   ├── 首页 AI 入口
│   │   └── AIChatContainer（全屏覆盖）
│   └── ArticleDetailView
│       ├── HTMLWebView / 正文选词菜单
│       ├── AI 悬浮按钮
│       └── AIChatContainer（全屏覆盖）
├── 热榜 Tab / NavigationStack
├── 我的 Tab / NavigationStack
│   └── SettingsView
│       └── AIConfigurationView
└── 共享 AI 状态
    ├── AIChatView
    ├── AIChatSessionListView
    ├── AIArticleContextSheet
    └── AIConfirmationDialog
```

### 2.1 页面层级原则

- **手机**：首页/正文是底层页面；AI 对话是全屏覆盖；Session 列表和上下文详情是对话页之上的 Sheet。
- **平板与桌面宽屏**：AI 对话采用分栏，左侧 Session 导航、中央消息区、右侧可选上下文栏；不再层层弹 Sheet。
- **首版不新增第四个 Tab**：AI 是阅读辅助能力，而非与“日报/热榜/我的”平级的信息域。

## 3. 全局视觉系统

## 3.1 色彩系统

### 3.1.1 品牌与中性色

| 语义令牌 | 浅色模式 | 深色模式 | 使用场景 |
|---|---:|---:|---|
| 纸底 `paper` | `#F9F6EF` | `#141311` | 页面、导航栏、TabBar、AI 对话背景 |
| 纸面浮层 `paperElevated` | `#FFFEFA` | `#1F1D19` | 输入框、引用区、设置行、Session 选中背景 |
| 浓墨 `ink` | `#26221B` | `#E8E3D8` | 主标题、正文、选中态 |
| 淡墨 `inkSecondary` | `#706B5E` | `#A29C8C` | 辅助文字、时间、占位文本、非当前 Session |
| 靛蓝 `indigo` | `#2C4A7C` | `#94ADDA` | 唯一主交互色：发送、链接、当前 Session、焦点 |
| 髮丝线 `hairline` | `rgba(38,34,27,.14)` | `rgba(232,227,216,.16)` | 分隔、描边、导航栏底线 |

### 3.1.2 功能色

| 功能色 | 浅色模式 | 深色模式 | 使用场景与限制 |
|---|---:|---:|---|
| 成功 | `#3F6B45` | `#8FBE91` | 连接测试成功、工具调用完成；不用于主按钮 |
| 警告 | `#8A5A20` | `#D9A35B` | 上下文已压缩、接近长度限制、工具能力不完整 |
| 错误 | `#A9342A` | `#E37B69` | 鉴权/请求/删除危险动作、字段错误 |
| 信息 | `#2C4A7C` | `#94ADDA` | 当前模型、搜索进行中、上下文提示 |
| 朱砂品牌警示 | `#B73729` | `#E06C58` | 离线、删除确认、不可逆警示；避免大面积铺底 |

### 3.1.3 对比度规则

- `ink` / `paper`、`ink` / `paperElevated`：正文与标题必须达到 **4.5:1**。
- `inkSecondary` 仅用于 12pt 以上的辅助文字；如验证低于 4.5:1，实际实现应提高不透明度或切换至 `ink`，不得以“辅助信息”为理由豁免。
- 白字仅置于靛蓝或朱砂实色按钮上；最低 14pt/600，确保 4.5:1。
- 功能状态不能只靠颜色：同时使用图标、文字和可访问性值。

## 3.2 字体规范

字体族延续现有系统：

- **结构文字**：`STSongti-SC-Black` / `STSongti-SC-Bold`，仅用于刊头、页面标题、Session 标题和节标题。
- **正文与控件**：iOS 系统字体 `-apple-system`，用于消息正文、输入、按钮、标签、辅助信息。
- **数字**：系统字体 + tabular/monospaced digits，用于进度和时间。

| 层级 | 字体 | 字号 | 字重 | 行高 | 使用场景 |
|---|---|---:|---:|---:|---|
| H1 | 宋体 Black | 30–31pt | 900 | 1.20 | 首页大标题，保持现有 31pt |
| H2 | 宋体 Black | 24–26pt | 900 | 1.25 | 文章标题、宽屏对话页主标题 |
| H3 | 宋体 Bold | 19–20pt | 700 | 1.30 | Session Sheet 标题、上下文详情标题 |
| H4 | 宋体 Bold | 16–17pt | 700 | 1.35 | Session 标题、设置分组内标题 |
| 正文 L | 系统 | 17pt | 400 | 1.62 | AI 回答、长文本阅读 |
| 正文 M | 系统 | 16pt | 400 | 1.55 | 用户消息、输入框、表单值 |
| 标签 | 系统 | 14pt | 500–600 | 1.35 | 按钮、工具状态、来源标题 |
| 辅助 | 系统 | 12–13pt | 400 | 1.45 | 时间、模型名、上下文状态、错误解释 |
| 微型 | 系统 | 11pt | 500 | 1.35 | 仅用于紧凑徽标；不可承载关键信息 |

规则：

- 消息正文默认 17pt，不低于 16pt；一行建议 28–42 个中文字符，宽屏最大正文宽度 720pt。
- 支持动态字体；放大至 200% 时不得裁切消息、按钮标签或错误文本。
- 超大动态字体下，顶部栏标题允许两行，次要按钮移入更多菜单。
- 不使用全大写；英文模型名保持原拼写。

## 3.3 间距与尺寸

**基础单位：4pt**。主节奏：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`。

| 用途 | 数值 |
|---|---:|
| 手机页面水平边距 | 16pt |
| 平板中央内容水平边距 | 24–32pt |
| 消息组间距 | 20pt |
| 同一消息内部间距 | 8–12pt |
| 卡片/引用区内边距 | 12–16pt |
| 输入框内边距 | 12pt |
| 列表行最小高度 | 52pt；重要入口 56pt |
| 控件最小触控区 | 44×44pt |
| 悬浮按钮 | AI 50pt；阅读进度 54pt |
| 悬浮按钮间距 | 10pt |
| 导航栏分隔线 | 0.5–0.7pt |
| 常规圆角 | 9–12pt |
| 输入框圆角 | 14pt |
| 小徽标圆角 | 3–6pt；胶囊状态用全圆角 |

层次规则：

- 不使用阴影表达层级；使用纸面色差、髮丝线和留白。
- 不进行卡片套卡片。文章上下文条、重点引用和工具状态在同一消息区内使用不同的边线方向区分。
- 分栏宽度：Session 侧栏 280–320pt；上下文侧栏 300–360pt；中央消息区最小 420pt、最大 760pt。

## 3.4 图标规范

- 使用 SF Symbols，线性/填充风格随状态切换，避免自制风格冲突。
- AI 入口使用“知”字章或统一 AI 符号；不可用闪光、魔法棒作为主要品牌符号。
- 图标视觉尺寸 16–20pt，触控区仍至少 44pt。
- 所有纯图标按钮提供可读标签：如“关闭 AI 对话”“新建对话”“停止生成”。

## 4. 基础组件规格

## 4.1 按钮

### 主要按钮

- 背景：`indigo`；文字：白色；高度 44–48pt；圆角 10pt。
- 用于：保存 AI 配置、确认发送、测试连接的主动作。
- 按下：背景加深 8%，`scale 0.97`，时长 90ms；释放 140ms ease-out。
- 禁用：背景 `indigo` 35% 不透明度，文字 65%，不可触发触觉反馈。
- 加载：保持宽度，文字切换为进度指示 + “正在连接”；禁用重复提交。

### 次要按钮

- 背景：`paperElevated`；0.7pt `hairline` 描边；文字 `indigo` 或 `ink`。
- 用于：查看上下文、添加当前文章、重试。
- 按下：背景切换为 `indigo` 8% 混合色，`scale 0.98`。

### 文字按钮

- 无背景，文字 `indigo`，最小 44pt 触控区。
- 用于：复制、重新生成、取消、展开全文。
- Hover（指针设备）：`indigo` 8% 底色；手机无悬停依赖。

### 危险按钮

- 默认白/纸色底 + `cinnabar` 文字；最终确认可用朱砂实底白字。
- 用于：删除 Session、替换上下文、清除 API Key。
- 必须二次确认，不得与“取消”并排同色。

## 4.2 输入框

### 聊天输入框

- 容器：`paperElevated`，0.7pt `hairline`，14pt 圆角。
- 高度：最小 52pt，最大约屏幕高度 32%；内容超出后内部滚动。
- 默认占位：“向当前文章提问……”或“输入问题……”。
- 聚焦：描边改为 1.5pt `indigo`，不使用发光阴影。
- 附属操作：右下角发送/停止按钮；左下角显示模型或上下文字数状态。
- 输入中立即启用发送；空白字符不启用。
- 生成中防重复提交：发送按钮变为停止，不允许并发第二条用户消息。

### 配置表单输入

- 标签永久位于输入框上方，不用 placeholder 代替标签。
- Endpoint/模型：失焦验证格式；API Key：仅提交时验证存在性，默认隐藏，可切换显示。
- 错误文字位于字段下方 4pt，12–13pt 错误色，并包含修复建议。
- 错误字段描边 1.5pt 错误色；焦点与错误同时存在时错误色优先。

## 4.3 消息与卡片

### 用户消息

- 手机：右对齐，最大宽度 86%；靛蓝 10% 浅底或靛蓝实底白字二选一。为保持刊物克制，规格采用 **靛蓝 10% 浅底 + 浓墨字**。
- 圆角 12pt，右下角 4pt，内边距 12×14pt。
- 时间与状态放在消息外下方，不挤入正文。

### AI 消息

- 左对齐，不强制包裹为浮卡；正文直接排在纸底上。
- 左侧用 2pt 靛蓝短竖线或“知”字小章标识来源。
- 操作栏位于消息下方：复制、重新生成、来源，均为文字按钮。

### 文章上下文条

- 位于导航栏下方、消息滚动区上方，可折叠。
- `paperElevated` 背景，底部髮丝线，无阴影。
- 内容：类型标签“当前文章”、一行标题、状态“已引入全文/已压缩”、查看和移除。
- 标题超长最多两行；大字号下操作按钮移至第二行。

### 重点引用

- 作为第一条用户消息之前的引用块，左侧 3pt `indigo`，背景 `paperElevated`。
- 显示 3–4 行，支持展开；不重复展示全文上下文。

### 来源卡片

- 单列列表，不做多张营销式卡片网格。
- 每条：序号、来源标题、域名、相关摘要；最小高度 56pt。
- 外链图标带 `aria-label`/VoiceOver 标签“在浏览器打开来源”。

## 4.4 标签与徽标

| 类型 | 样式 | 文案示例 |
|---|---|---|
| 模型徽标 | `paperElevated` + 髮丝线 + 淡墨文字 | `gpt-4.1-mini` |
| 搜索中 | 信息色 8% 背景 + 信息色文字 + spinner | “正在搜索” |
| 搜索完成 | 成功色 8% 背景 + 成功色文字 + checkmark | “已检索 4 个来源” |
| 已压缩 | 警告色 8% 背景 + 警告文字 + 图标 | “上下文已压缩” |
| 中断 | 髮丝线描边 + 淡墨文字 | “回答已停止” |
| 错误 | 错误色 8% 背景 + 错误文字 | “请求失败” |

## 4.5 弹窗与 Sheet

- 手机 Session 列表：底部 Sheet，默认 70% 高，可上拉至全屏。
- 上下文详情：中等 Sheet，正文长时可全屏滚动。
- 删除/替换：系统确认对话框；标题说明对象，正文说明不可逆影响。
- 不使用居中小弹窗承载长对话或长表单。
- Sheet 顶部拖拽条仅作为视觉提示，不替代“关闭”按钮的可访问入口。

```text

├── NavigationBar

│   └── TrailingToolbar
│       └── AIButton（新增）

    ├── DatelineSection*
    │   └── StoryRowView*
    └── HistoryPaginationFooter

```

### 新增内容

- 导航栏右上角新增 44×44pt AI 图标按钮，图形采用靛蓝“知”字/气泡组合。
- 点击：打开最近使用的独立 Session；若无独立 Session，则显示空白新对话。
- 长按/指针提示：“AI 搜索”。
- 首页新建 Session 默认无文章上下文。

### 状态

- 未配置 Endpoint：按钮仍可点击，打开 AI 空态并显示“尚未配置 AI 服务”与主按钮“去配置”。
- 有未完成草稿：不在首页按钮显示红点，避免打扰阅读；进入后恢复草稿。
- 生成进行中切回首页：AI 按钮可显示细小进度环，但必须提供 VoiceOver 值“AI 正在生成回答”。

### 过渡

- 打开 AI：系统全屏 cover，自底向上 280–320ms。
- 关闭：系统下滑/关闭按钮；无装饰性回弹。
- Reduce Motion：改为 160ms 淡入淡出。

### AI 悬浮按钮

- 50×50pt，位于右下安全区上方 18pt、右边 18pt。
- 回顶按钮出现后，AI 按钮向上保持 10pt 间距；两者共享垂直轴。
- 默认：`paperElevated` 背景、1pt 靛蓝描边、靛蓝“知”字。
- 按下：背景为靛蓝 10%，缩放至 0.96，90ms；触发轻触觉反馈。
- 点击：打开当前文章最近 Session；若没有，则创建绑定当前文章的新 Session。
- VoiceOver：“就当前文章询问 AI”；提示：“打开带有当前文章上下文的对话”。

### 正文选词菜单

- 保留系统选区高亮与手柄。
- 菜单次序：系统复制/查询等操作之后追加“AI 搜索”；不覆盖系统菜单。
- 点击后：
  1. 获取并规范化选区；
  2. 打开一个绑定当前文章的新 Session；
  3. 顶部显示当前文章上下文；
  4. 选词显示为重点引用；
  5. 输入框预填选中文字，不自动发送；
  6. 输入框获得焦点，用户可补充“解释/查证/总结”。
- 选区为空不响应；超出长度时截取并在输入框上方显示警告“选中内容较长，已保留前 N 字”，提供“返回重新选择”。

### 正文与 AI 同时呈现方式

- 选词阶段：系统菜单浮在正文之上，正文保持可见。
- 正式对话阶段：AI 全屏覆盖正文；正文保留在底层，不重载、不归零滚动位置。
- 关闭 AI：回到原阅读位置；选区是否保留遵循系统默认，不强行恢复手柄。

### 加载与错误

- 文章尚未完成加载：AI 按钮禁用并显示 35% 不透明度；标签“文章加载完成后可用”。
- 正文加载失败：允许打开独立 AI 对话，但不声称已引入全文；上下文条显示“正文不可用，仅包含标题”。
- 正文纯文本提取中：按钮可打开，顶部显示 1 行轻量进度“正在准备文章上下文”，发送暂禁用，完成后自动恢复。

  - “当前会话使用《文章 A》，你正在阅读《文章 B》。”

- 消息按时间顺序，自然单列；新消息完成后不强制跳底，只有用户处于底部附近时自动跟随。
- 用户上滑查看旧内容时，底部出现“回到最新”按钮，44pt 触控区。
- 流式回答以文字自然增长，不使用逐字符闪烁光标；末尾显示小型 3 点进度。
- 代码块、引用、列表和链接遵循系统可选择文本；横向长代码块内部滚动。
- AI 回答可被选择复制，操作栏仅在消息完成或中断后出现。

### 输入区

- 使用底部安全区 inset，不被键盘遮挡。
- 默认 1–4 行；继续增长后内部滚动。
- 未输入：发送禁用。
- 输入有效：发送按钮靛蓝实底；点击后立即：
  - 将用户消息插入列表；
  - 按钮变为停止；
  - 输入框清空但将文本存为可恢复请求；
  - 在 600ms 内忽略重复触发。
- 生成时不允许发送第二条；用户可以停止后继续追问。
- 关闭页面时若有草稿，本机保存；再次打开恢复。

### 动作与即时反馈

| 动作 | 视觉反馈 | 触觉/防重 |
|---|---|---|
| 发送 | 按钮缩放 0.96，发送图标切停止方形；用户消息立即入列 | 轻触觉；600ms 节流 + generation 状态锁 |
| 停止 | 停止按钮按下变深；AI 消息尾部标记“回答已停止” | 中触觉；取消任务仅执行一次 |

| 新建 Session | 列表插入新空会话并切换 | 现有生成先确认停止，或保存中断状态 |
| 删除 Session | 系统确认；删除后淡出 160ms | 危险触觉；不可撤销时明确提示 |

## 6. 加载、空、错误与网络状态

## 6.1 加载策略

| 场景 | 组件 | 规则 |
|---|---|---|
| Session 首次读取 | 3–5 行 Session 骨架 | 使用 `paperElevated` 与髮丝线，不闪白；0.9s 淡入淡出，Reduce Motion 静态 |
| 对话历史读取 | 消息块骨架 | 只在冷启动读取超过 200ms 时显示，避免快速闪烁 |
| AI 生成 | 流式文字 + 末尾进度点 | 不覆盖已有回答，不用全屏 spinner |
| 搜索工具 | 内联工具状态行 | 明确“正在搜索”，完成后显示来源数 |
| 上下文准备 | 上下文条内细进度 | 发送按钮暂禁用，正文仍可查看 |
| 连接测试 | 按钮内 ProgressView | 保持按钮宽度，禁止重复提交 |

## 6.2 空状态

### 文章 Session 空态

- 标题：“从这篇文章开始问”。
- 说明：“已将《文章标题》作为当前对话背景。”
- 建议问题：
  - “用三句话总结这篇文章”
  - “解释文中的核心概念”
  - “查证文章中的关键结论”
- 建议问题是次要按钮，点击只填入输入框，不自动发送。

### 独立 Session 空态

- 标题：“今天想了解什么？”
- 说明：“可以提问、比较观点，或让模型按需搜索。”
- 不暗示一定联网。

## 6.3 错误状态

- **局部优先**：发送失败显示在对应消息下；不要替换整页会话。
- 错误行包含图标、简短原因、重试按钮、可选“查看详情”。
- 401/403：文案“认证失败，请检查 API Key”，操作“去设置”。
- 404：文案“未找到兼容接口，请检查 Endpoint 路径”。
- 429：文案“请求过于频繁，请稍后重试”；如有 `Retry-After`，显示可重试时间。
- 5xx/超时：保留草稿和部分回答，操作“重试”。
- 流中断：已收到文本保留，标记“回答中断”；可“继续生成”或重新发送。
- 搜索工具失败：回答仍可继续时显示警告“搜索未完成，以下回答可能仅基于模型知识”。

## 6.4 离线状态

- 对话页顶部使用现有 `OfflineBanner` 同源样式：朱砂 8% 底、朱砂图标、浓墨文字。
- 文案：“当前离线，可查看已保存会话，暂时无法发送消息。”
- 输入框保留草稿；发送禁用但不清空。
- Session 切换、复制、查看文章上下文继续可用。

## 7. 动效与交互时序

## 7.1 动效令牌

| 类型 | 时长 | 缓动 | 使用 |
|---|---:|---|---|
| 即时按压 | 90ms | ease-out | 按钮缩放/变色 |
| 状态恢复 | 140ms | ease-out | 按钮释放、复制成功反馈 |
| 内容淡入 | 160ms | ease-out | Session 切换、来源出现、错误行 |
| 行插入/删除 | 180ms | ease-out-quart | Session 增删、消息操作栏 |
| 全屏/Sheet 转场 | 280–320ms | 系统 ease-out | AI 页面、Session Sheet |
| 回顶滚动 | 280ms | ease-out | 延续现有阅读进度按钮 |

- 禁止涟漪效果：iOS 原生环境采用颜色、缩放与触觉反馈，避免 Android 化。
- 禁止弹簧回弹用于 AI 页面主要转场；现有“我的”胶囊切换可保留原弹簧动效。
- 动画只作用于 `opacity`、`scale`、`transform`；不对复杂高度反复动画导致抖动。

## 7.2 Reduce Motion

- 全屏/Sheet 改为 160ms 淡入淡出。
- 消息流不做位移动画。
- 骨架不脉动，使用静态占位 + 可访问性“正在加载”。
- 回顶可立即跳转，不强制平滑滚动。

## 7.3 防重复与并发规则

- 单个 Session 同时只允许一个生成任务。
- 发送后 600ms 内忽略重复点击；生成状态锁优先于时间节流。
- 测试连接与保存各自只有一个活动任务。
- 切换 Session、删除当前 Session、关闭页面时若正在生成：先停止并保存为“中断”，再执行操作。
- 任何异步结果必须按 Session ID 校验，防止旧请求写入新 Session。

## 8. 响应式与跨设备适配

> 本项目当前是原生 iOS 应用。以下断点作为 SwiftUI 可用宽度/窗口宽度的设计规则，同时满足后续 iPad 多窗口与桌面化需求。功能不因屏幕变窄而消失，只改变呈现容器。

## 8.1 `<480pt`：紧凑手机

- 单列布局。
- AI 对话全屏；Session 列表为底部 Sheet；上下文详情为 Sheet。
- 顶栏仅保留关闭、Session 标题、加号、更多；次要动作进入菜单。
- 消息宽度：用户 ≤86%，AI 100% 内容宽度。
- 页面水平边距 16pt；极窄 320pt 保持 12pt 最低边距。
- 悬浮按钮右/下 16–18pt，不遮挡正文链接和系统手势区。
- 输入区最大高度 32vh；键盘弹出后消息区保持至少 160pt 可见。

## 8.2 `≥480pt 且 <768pt`：大手机/横屏手机

- 仍为单列，但中央消息内容最大 640pt 居中。
- Session Sheet 最大宽度 560pt；横屏可采用居中页面 Sheet。
- 上下文条操作可并排显示“查看”和更多菜单。
- 横屏时输入框不超过内容宽度，左右留出 24pt。

## 8.3 `≥768pt 且 <1200pt`：平板/中等窗口

- AI 对话采用两栏：
  - 左侧 Session 侧栏 280pt，可折叠；
  - 右侧主对话区占余宽。
- Session 侧栏收起后通过导航栏按钮重新打开为抽屉/Popover。
- 文章上下文保持主区顶部横条；详情以右侧 Popover 或 Sheet 打开。
- 首页/正文维持现有 NavigationSplit/Stack 逻辑，不新增汉堡菜单；Session 侧栏按钮采用 `sidebar.left` 图标。
- 消息区最大 720pt 居中，避免横向拉满。

## 8.4 `≥1200pt`：大平板横屏/桌面宽窗口

- 三栏布局：
  - Session 侧栏 300pt；
  - 对话主区 min 520pt、max 760pt；
  - 文章上下文侧栏 320pt，可折叠。
- Session 列表始终可见，不再通过 Sheet 切换。
- 文章上下文侧栏显示标题、状态、纯文本预览和替换操作。
- 顶部导航只承载当前 Session 标题、模型和新建；关闭按钮在独立窗口环境可转换为返回/收起 AI。
- 页面最大总宽 1440pt，超出后两侧留白；不把消息行拉至 4K 全宽。
- 支持指针 hover、右键 Session 菜单和键盘快捷键：
  - `⌘N` 新建 Session；
  - `⌘K` 打开 Session 搜索；
  - `⌘Return` 发送；
  - `Esc` 停止生成或关闭最上层 Sheet。

## 8.5 侧栏折叠规则

- ≥1200pt：两侧栏默认展开。
- 768–1199pt：Session 栏默认展开，上下文栏折叠。
- <768pt：两栏都转换为 Sheet/导航层，不保留占宽侧栏。
- 不使用 Web 式汉堡菜单取代 iOS 主 Tab；只有 AI 内部 Session 导航使用侧栏/抽屉转换。

## 9.1 语义结构映射

原生 SwiftUI 应使用等价可访问性容器；若生成 Web 预览或跨平台实现，语义标签如下：


- 标题顺序保持 H1→H2→H3，不因视觉字号跳级。
- Session 行使用可选择项语义；当前项设置 selected 状态。
- 消息流使用有序阅读顺序，工具状态归属于对应 AI 消息。

## 9.2 键盘与焦点

- 所有交互元素可通过键盘访问，焦点顺序：顶部导航 → 上下文条 → 消息操作 → 输入区。
- 焦点指示：2pt 靛蓝外框，offset 2pt；错误字段使用错误色框，但仍提供可见 focus ring。
- 打开 Session Sheet：焦点移至标题；关闭后回到 SessionPickerButton。
- 表单提交失败：焦点移至第一个错误字段，并朗读错误摘要。
- 新 AI 回答完成：不强制抢焦点；通过可访问性通知“回答完成”。
- 流式增量不逐字朗读，最多按段落节流；停止后朗读“回答已停止”。

## 9.3 标签与替代文本

| 控件 | 可访问性标签示例 |
|---|---|
| 首页 AI 图标 | “AI 搜索” |
| 正文悬浮按钮 | “就当前文章询问 AI” |
| Session 标题按钮 | “当前对话：确认偏误的形成，轻点切换” |
| 新建按钮 | “新建对话” |
| 发送按钮 | “发送消息” |
| 停止按钮 | “停止生成回答” |
| 上下文条 | “当前文章上下文：为什么人会产生确认偏误，已引入全文” |
| 来源链接 | “来源 1，标题，在浏览器打开” |
| 纯装饰章记 | 隐藏于辅助功能树，避免重复朗读 |

- 文章图片沿用内容性替代文字；无描述时标记为装饰，不朗读文件名或 URL。
- 状态图标必须搭配文字或 accessibility value。

## 9.4 触控与文本缩放

- 所有按钮/列表项最小 44×44pt；Session 行最小 72pt。
- 文本缩放到 200% 时：
  - 顶栏按钮不覆盖标题；
  - 上下文条可纵向增长；
  - 消息动作栏可换行或收进更多菜单；
  - 配置表单标签与输入框改为上下排列；
  - 不截断错误修复建议。
- 不锁定横竖屏，不禁用系统缩放或动态字体。

## 9.5 颜色与非视觉反馈

- 选中 Session：颜色 + 左侧标记 + “当前”可访问性状态。
- 成功/警告/错误：颜色 + SF Symbol + 文案。
- 搜索工具：进度动画 + 状态文字；Reduce Motion 下以文本更新替代动画。
- 链接除颜色外需具备下划线或外链图标，确保色觉差异用户可识别。

## 10. 文案规范

- 功能名统一使用“AI 搜索”，空态说明可写“文章问答”；不承诺每次都联网。
- 搜索真实状态：
  - 开始：“正在搜索”
  - 有来源：“已检索 4 个来源”
  - 无来源：“模型未返回来源”
  - 工具失败：“搜索未完成，回答可能仅基于模型知识”
- 上下文状态：
  - “已引入全文”
  - “上下文已压缩”
  - “仅包含标题”
- 错误文案结构：发生了什么 + 用户能做什么；不展示内部栈、Token 或敏感请求。
- 删除确认必须点名对象：“删除对话‘确认偏误的形成’？”

## 11. 设计验收清单

### 结构一致性

- [ ] 首页保持现有 List + 大标题结构，只在工具栏增加 AI 入口。
- [ ] 正文保持现有 ScrollView + HTMLWebView，不引入第二层正文滚动。
- [ ] AI 全屏覆盖后关闭可恢复原阅读位置。
- [ ] 手机 Session 列表使用 Sheet，平板/桌面使用侧栏。
- [ ] 设置沿用现有纸面 List 分组。

### 视觉一致性

- [ ] 仅靛蓝承担主交互；朱砂只用于警示/危险。
- [ ] 无渐变、毛玻璃、通用阴影和“万物皆卡片”。
- [ ] 宋体只用于结构文字；消息正文使用系统字体。
- [ ] 所有边距、圆角、髮丝线符合 4pt 节奏与现有 DS 令牌。

### 交互完整性

- [ ] 选词进入时预填、不自动发送，全文上下文可见。
- [ ] 已有 Session 不被当前文章静默覆盖。
- [ ] 生成中可停止，不能重复发送或串 Session。
- [ ] 搜索工具状态与来源均基于真实 Endpoint 返回。
- [ ] 未配置、401、429、断流、离线、持久化失败均有局部可恢复界面。

### 响应式与可访问性

- [ ] 320pt、480pt、768pt、1200pt 四档布局均有明确降级/增强方式。
- [ ] 正常文本对比度 ≥4.5:1，大文本 ≥3:1。
- [ ] 交互元素 ≥44pt，焦点清晰，键盘无陷阱。
- [ ] 200% 文本缩放、VoiceOver、Reduce Motion、横屏可用。
- [ ] 图标按钮、非文本内容和状态均有准确标签。

## 12. 最终设计结论

本功能应被设计为现有“今日刊”阅读体验中的一层**可随时进入、可完整退出、上下文透明的批注式 AI 工作区**：

- 正文选词菜单负责精确发问；
- 正文悬浮按钮负责围绕当前文章持续讨论；
- 首页入口负责独立对话；
- Session 导航负责长期组织；
- 文章上下文条负责建立信任；
- 搜索工具状态与来源负责可追溯性。

视觉上不另造一套“AI 风格”，而是严格复用暖纸、浓墨、靛蓝、宋体和文武线，使 AI 能力看起来像 DailyReader 原生长出来的一部分。
