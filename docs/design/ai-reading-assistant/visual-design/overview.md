# AI 阅读助手可视化 UI 设计交付

## 完成内容

- 制作一套 5 屏移动端 UI 设计图，覆盖正文选词与悬浮入口、文章上下文对话、搜索来源、Session 切换、首页独立空态和 AI Endpoint 配置。
- 输出可缩放浏览的 HTML 设计板与 1510×1600 PNG 总览图。
- 视觉延续现有“今日刊”设计系统：暖纸、浓墨、靛蓝主交互、朱砂警示、宋体结构标题和髮丝线分层。

## 关键设计决策

- AI 仍是阅读辅助能力，不新增第四个一级 Tab。
- 选中文字仅预填输入框，不自动发送；完整文章作为 Session 的稳定上下文快照。
- AI 对话全屏覆盖正文，但保留底层文章和阅读位置。
- 旧 Session 保留原文章上下文，发生文章冲突时必须显式新建或替换。
- 只有 Endpoint 实际返回搜索工具事件和引用时，界面才展示检索状态与来源。
- API Key 仅表达为本机钥匙串存储，不在错误信息或界面中回显。

## 验证结果

- HTML 包含 5 个完整手机屏幕，结构和 CSS 括号完整。
- PNG 成功导出为 1510×1600。
- 未使用渐变、外部占位图、通用 AI 发光视觉或卡片套卡片。
- 关键配色对比度：浓墨/纸底 14.66:1，辅助文字/纸底 4.92:1，白字/靛蓝 8.83:1，均达到 WCAG AA。

## 后续建议

- 确认本版视觉方向后，可继续补充文章上下文冲突、流式中断、离线、请求失败和 iPad 双栏/三栏界面。
- 进入 SwiftUI 实现前，建议先以正文选词桥接和全屏对话容器作为关键路径验证样本。
