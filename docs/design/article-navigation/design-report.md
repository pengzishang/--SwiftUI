# DailyReader 文章正文导航重设计

## 结论先行

推荐采用 **方案一「题随文隐」**：正文顶部完整展示标题；标题离开视野后，导航栏才显示紧凑上下文标题；点击紧凑标题可查看全文。它最符合移动阅读习惯，也能直接复用现有正文标题与滚动监听，改动和回归风险最低。

建议吸收方案三的一个能力：紧凑标题可点击展开完整标题，但暂不加入持续跑马灯或复杂阅读进度胶囊。

---

## 1. 现状分析

### 当前实现

- `DailyReader/Features/Detail/ArticleDetailView.swift:60–65` 已在正文内使用 26pt 宋体完整展示标题，且不限制行数。
- `ArticleDetailView.swift:197–198` 又将同一标题传给系统 `.navigationTitle(...)`，显示模式为 `.inline`。
- `ArticleDetailView.swift:200–264` 右侧存在操作菜单，系统导航栏还需预留返回区域，因此中央标题可用宽度有限。
- `DailyReader/Features/Detail/ArticleScrollObserver.swift:119–172` 已监听 `UIScrollView.contentOffset`，可直接驱动导航折叠状态。

### 根因

系统 inline navigation title 本质是有限宽度的单行上下文标签。标题越长、屏幕越窄、系统字号越大，越容易被截断。继续微调字体或压缩操作按钮只能延后问题，不能解决问题。

### 设计原则

1. **正文标题负责完整表达，导航标题负责位置提示。**
2. 返回、收藏、分享等操作不与完整标题争夺同一横向空间。
3. 只在滚动导致上下文丢失时显示导航标题，避免重复。
4. 所有视觉截断都必须有查看完整内容的入口，VoiceOver 始终读取全文。
5. 延续「今日刊」：`DS.paper`、`DS.ink`、宋体标题、髮丝线，不引入阴影堆叠或过度毛玻璃。

# 方案一：题随文隐

## 核心概念

**沉浸式大标题 + 滚动折叠导航。** 文章开头由正文大标题完整表达；标题越过导航区域后，导航中央才显示紧凑标题。

## 页面结构

1. 系统返回按钮，44×44pt。
2. `ToolbarItem(placement: .principal)` 自定义紧凑标题。
3. 右侧 44×44pt 操作菜单。
4. 正文保留当前 26pt 宋体完整标题、题下信息与文武线。

## 状态

- **初始 0–24pt：** 导航中央留白；正文大标题最多自然换行 4 行。
- **过渡 24–64pt：** 紧凑标题透明度 0→1、向上位移 4→0pt；导航底部髮丝线淡入。
- **稳定 ≥64pt：** 16–17pt 宋体单行标题；视觉省略但可点击。
- **展开：** 点击紧凑标题，在导航下方展示完整标题、来源与阅读进度。
- **反向滚动：** offset <32pt 才恢复初始态，形成迟滞区，避免边界抖动。

## 动效

- 进入 220ms，退出 165ms。
- `easeOut` 对应 `cubic-bezier(0.16, 1, 0.3, 1)` 的克制减速感。
- 只改变 `opacity` 与 `transform`，不逐帧动画导航高度。
- 快速滚动直接收敛到最终状态，不重复播放。
- Reduce Motion：在阈值处无动画切换；弹层使用瞬时出现。

## 响应式

- 320–375pt：紧凑标题单行，左右最少各保留 52pt；动态字号 AX3 以上改显示“文章”。
- 390–430pt：紧凑标题最大约 220pt。
- 横屏：最大宽度 320pt，不拉满。
- iPad 分栏：依据容器宽度设 240–360pt 上限。
- 中英混排：禁止字符压缩过度，使用尾部省略；完整标题入口不变。

## 可访问性

- principal 按钮标签为完整标题，提示“轻点查看完整标题”。
- 正文标题使用 `.accessibilityAddTraits(.isHeader)`。
- 弹层出现后将 VoiceOver 焦点移至完整标题。
- 44×44pt 点击区；键盘 Return/Space 可展开。

## 优势 / 风险 / 成本

- **优势：** 沉浸感最好；与现有代码兼容度最高；信息职责清晰。
- **风险：** 稳定态仍不能视觉显示所有文字，但完整内容可达。
- **成本：** 低—中。

## SwiftUI 实现建议

- 扩展 `ArticleScrollMetrics`，将 `offset` 同步到 `@State private var articleOffset`。
- 使用 `ToolbarItem(placement: .principal)` 替代 `.navigationTitle(viewModel.shareTitle)` 的视觉职责。
- 提取 `CollapsingArticleTitle`，输入 `title`、`offset`、`dynamicTypeSize`、`reduceMotion`。
- 用 `.popover`（iPad）与 `.sheet` 或导航下 overlay（iPhone）展示完整标题。

# 方案二：双层报眉

## 核心概念

**操作层固定 + 标题层自适应。** 将横向竞争改为纵向分层：第一层只放导航操作，第二层使用完整宽度展示标题。

## 页面结构

- 第一层 50pt：返回、可选来源短标签、操作菜单。
- 第二层：左右 16pt，16–17pt 宋体，最多两行，底部髮丝线。
- 正文大标题调整为 22–26pt；若标题层已完整呈现，可通过视觉权重降低重复感。

## 状态与动态

- 初始总高度约 94–112pt。
- 0–88pt 滚动区间内，标题层向上平移并通过 `clipShape` 收起。
- ≥88pt 只保留操作层；中央显示“文章”或来源短标签。
- 点击中央区域可临时重新展开标题层。
- 240ms 进入、180ms 退出；Reduce Motion 直接切换。

## 响应式

- 320–375pt：16pt/21pt，两行。
- 390–430pt：17pt/22pt，两行。
- iPad 分栏允许三行，但上限 112pt。
- AX 字号：标题层随内容增高，操作按钮始终独立一行；最适合 200% 字号。

## 可访问性

- 视觉和语义均完整，VoiceOver 顺序为返回→标题→操作→正文。
- 标题层标记为 header；收起后避免生成重复可访问元素。
- 指针悬停只提供轻微底色，不依赖 hover 才能操作。

## 优势 / 风险 / 成本

- **优势：** 标题完整性和大字号适配最佳。
- **风险：** 首屏占高；与正文标题重复；自定义顶栏需仔细维护返回手势和安全区。
- **成本：** 中。

## SwiftUI 实现建议

- 使用 `.safeAreaInset(edge: .top, spacing: 0)` 构建双层栏，必要时隐藏系统导航栏视觉但保留 `NavigationStack`。
- 标题层使用 `ViewThatFits` / `dynamicTypeSize` 分支和 `lineLimit(2...3)`。
- 通过 transform + clip 收起，避免持续动画 frame 高度。

# 方案三：墨迹岛

## 核心概念

**标题胶囊 + 阅读进度联动。** 正文完整标题离开视野后，导航中央出现纸面胶囊，左侧朱砂刻度显示阅读进度。

## 页面结构

- 返回按钮。
- 34pt 紧凑胶囊：4pt 进度刻度 + 单行标题。
- 右侧操作菜单。
- 点击胶囊，在导航下展开完整标题、来源和百分比。

## 状态与动态

- 阅读进度 <12%：胶囊隐藏。
- ≥12%：200ms 淡入并上移 6pt。
- 进度仅更新刻度，不持续跑马灯；避免阅读干扰。
- 点击后完整标题面板 200ms 展开；继续滚动或再次点击收起。
- Reduce Motion：无位移，仅显隐；进度更新无动画。

## 响应式

- 320pt：胶囊最大宽 168pt。
- 390–430pt：最大 220–238pt。
- 横屏 / iPad：最大 320pt。
- AX 大字号：紧凑态改为图标 +“标题”，完整文本放入展开面板。

## 可访问性

- 胶囊为按钮，标签使用完整标题，值为“已阅读 N%”。
- 阅读进度不能只靠颜色表达。
- 展开面板有明确关闭动作和焦点管理。

## 优势 / 风险 / 成本

- **优势：** 品牌辨识度最高，利用现有阅读进度能力。
- **风险：** 胶囊容易被误读为标签；信息密度较高；状态测试更多。
- **成本：** 中—高。

## SwiftUI 实现建议

- 从 `ArticleReadingSession.progressPercentage` 读取百分比。
- 自定义 `ToolbarItem(.principal)`，用 `GeometryReader` 控制最大宽度。
- 展开内容使用 `presentationCompactAdaptation(.popover)` 或自定义 overlay。

# 推荐与最小原型

## 推荐

选择 **方案一「题随文隐」**，并加入“点击紧凑标题查看全文”。它没有试图把完整标题硬塞进导航栏，而是根据阅读阶段分配信息职责，符合原生阅读习惯，也最能保持「今日刊」的克制。

## MVP 范围

1. 用 principal 自定义标题取代系统 inline 标题的视觉输出。
2. 读取现有 scroll offset，完成：初始、过渡、稳定三态。
3. 64pt 进入 / 32pt 退出的迟滞阈值。
4. 点击紧凑标题显示完整标题。
5. Reduce Motion 与 AX 大字号降级。
6. 验证矩阵：320pt、390pt、430pt、iPad 分栏；1行/4行标题；100%/200% 字号；浅色/深色。
7. UI 测试：标题出现阈值、完整标题入口、返回与操作菜单始终可点击、VoiceOver 标签为全文。

# V2 补充：精确交互与统一组件规范

## 1. 导航标题的精确位置

采用 **均衡三槽导航**：

```text
| 48pt 返回热区 | minmax(0, 1fr) 中央标题槽 | 48pt 操作热区 |
```

- 导航内容高度 52pt，按钮视觉尺寸 36–40pt，但点击热区固定 44×44pt。
- 左右槽物理宽度必须相同，标题才是相对屏幕视觉居中，而不是相对剩余空间居中。
- 390pt 屏幕中央标题视觉最大宽度 220pt；320–375pt 为 168–196pt；430pt 为 238pt；iPad 分栏为 240–360pt。
- 中央使用 `ToolbarItem(placement: .principal)` 时，内部通过容器宽度约束保证左右按钮不被推动。
- 动态字体达到 AX3 后，紧凑态改为“文章标题”或“文章”，点击后完整展示，禁止缩小到不可读字号。

## 2. 具体滚动动画

| 阶段 | Scroll offset | 正文标题 | 导航标题 | 导航底线 |
|---|---:|---|---|---|
| 首屏 | 0–24pt | opacity 1；Y=0 | opacity 0；Y=6pt | 0% |
| 交接 | 24–64pt | opacity 1→0；Y 0→-8pt | opacity 0→1；Y 6→0pt | 0→100% |
| 稳定 | ≥64pt | 隐藏但保留正文语义 | 稳定显示 | 100% |
| 反向退出 | <32pt | 恢复 | 退出 | 逐渐隐藏 |

动效令牌：

- 导航标题进入：220ms，expo-out `cubic-bezier(0.16, 1, 0.3, 1)`。
- 导航标题退出：165ms，ease-in `cubic-bezier(0.7, 0, 0.84, 0)`。
- 髮丝线：180ms 透明度过渡。
- 只动画 `opacity` 和 `transform`；快速甩动时直接收敛到最终态。
- Reduce Motion：阈值处无位移切换，保留必要的瞬时显隐与状态反馈。

## 3. 右侧操作 Item 点击设计

### 触发按钮

- 默认：透明背景、靛蓝图标、44×44pt 热区、11pt 圆角。
- 按下 0–90ms：scale 1→0.92，出现靛蓝 17% 的“纸面压印”底色。
- 释放 90–210ms：scale 回到 1；菜单从右上触发点展开。
- 菜单展开时：按钮变为靛蓝实底、纸色图标，表示当前控制关系。

### 菜单

- 宽度 220–240pt，锚定右上按钮，距导航栏 4pt。
- 进入：210ms，opacity 0→1、translateY -7→0、scale .97→1。
- 退出：150ms，先淡出再移除。
- 每项最小高度 46pt，结构为 24pt 图标 + 标签 + 可选状态。
- 排序：分享、收藏/取消收藏、已读状态；分隔线后放“不感兴趣”等破坏性动作。
- 收藏采用乐观更新；完成后底部显示 1.8s 反馈条，可提供撤销。
- 不感兴趣不弹二次确认，先移动再提供“撤销”，降低确认疲劳。

## 4. 全局按钮设计语言：“纸面压印”

### 统一基础

- 圆角：普通按钮 9pt；导航图标按钮 11pt；不使用大药丸作为默认按钮。
- 高度：图标/文字按钮均至少 44pt。
- 交互色：统一使用 `DS.indigo`；危险动作使用 `DS.cinnabar`。
- 层级表达：使用纸色、髮丝线和墨色，不使用通用阴影。
- 按下反馈：80–100ms scale 0.92–0.96 + 背景色加深，不使用弹跳。

### 四类按钮

1. **导航图标按钮**：透明默认，按下出现靛蓝淡底；44×44pt。
2. **主按钮**：靛蓝实底、纸色文字；每个上下文最多一个。
3. **次级按钮**：透明纸面、靛蓝 35% 描边；用于关注、重试等。
4. **文字按钮**：无容器、靛蓝文字；用于取消和低优先动作。

### 完整状态

- Hover/Pointer：靛蓝 10% 底色。
- Focus：2pt 靛蓝外描边，offset 2pt。
- Active：缩放并加深底色。
- Disabled：整体 42% opacity，语义仍可朗读原因。
- Loading：保留原按钮宽度，用 ProgressView 替换前导图标。
- Success：短暂显示 checkmark 与反馈文案，不永久改为绿色按钮。

## 5. 作者头像与署名

### 正文布局

- 放置在文章完整标题下方、文武线上方。
- 结构：38pt 圆形头像 + 作者名/身份与阅读时长 + 36pt 高关注按钮。
- 作者名 14pt Semibold；身份与时长 12pt 淡墨。
- 头像使用 0.7pt 髮丝线，不加阴影；加载失败显示宋体“日”或作者首字。
- 点击导航紧凑标题后的完整标题面板中，复用 24pt 头像和作者名，帮助读者建立内容归属。

### 当前数据约束与落地

现有 `ArticleDetail` 和 `StorySummary` 没有结构化作者字段，但 HTMLWebView 已识别 `.author`、`.avatar`、`.meta`、`.source`：

1. Web 内容加载完成后，用 JavaScript 提取作者名、头像 URL、来源与简介。
2. 通过 WKScriptMessageHandler 回传 `ArticleAuthorMetadata`。
3. 原生层收到有效数据后显示 `ArticleBylineView`，并给 HTML 作者节点加隐藏类避免重复。
4. 无法提取时仅显示来源和日期；头像显示“日”占位，不虚构作者身份。
5. 头像 URL 必须沿用现有安全域名与加载策略，并提供失败占位。

建议模型：

```swift
struct ArticleAuthorMetadata: Equatable {
    let name: String?
    let avatarURL: URL?
    let bio: String?
    let source: String?
}
```

## 6. 推荐组件拆分

- `ArticleNavigationBar`：三槽导航与状态容器。
- `CollapsingArticleTitle`：滚动标题交接。
- `ArticleActionMenu`：分享、收藏、阅读状态与不感兴趣。
- `PaperPressButtonStyle`：全局按压动效与视觉令牌。
- `ArticleBylineView`：作者头像、署名与关注。
- `ArticleTitlePopover`：完整标题、24pt 作者头像与阅读进度。

# V3 修订：单一连续 WebView 正文

## 1. 对现有截图的判断

用户截图属于 **问答合集型正文**，不是“固定封面 + 原生标题 + 普通文章”的单一模板。当前视觉不协调主要来自：

1. 原生导航栏已经显示单行标题，正文中又可能存在标题，职责重复。
2. `ArticleDetailView` 在 WebView 前固定渲染 `detailImageURL`，但 HTML 内可能还有正文图片，形成双重媒体流。
3. 当前 HTML 图片统一 `margin: 14px 0`，没有区分段落后图片、连续图片、图片与图注。
4. WebView 禁用内部滚动，由外层 ScrollView 承载，并将高度设为 `max(measuredHeight, 520)`；短正文或高度回写延迟时可能出现假空白。
5. 如果通过透明度或位移“搬走”正文标题，而不真正移除布局盒子，也会留下明显空洞。

## 2. 推荐页面架构

采用：

```text
NavigationStack / 原生导航栏
└── 单一可滚动 WKWebView
    ├── 文章标题
    ├── 作者与来源（按数据存在与否渲染）
    ├── 文武线
    └── 连续 HTML 正文
        ├── 段落
        ├── 问题标题
        ├── 回答作者
        ├── 引用
        ├── 链接
        ├── 图片
        └── 图注 / 讨论入口
```

原生层只保留：返回、导航标题副本、操作菜单、系统分享、图片查看器和安全浏览器。标题、作者、hero、正文图片都属于 Web 文档，不能拆成两个独立滚动语境。

## 3. 标题滚动方式

- Web 标题在 DOM 中自然滚出视野，不动画其 opacity，也不对它做 translate。
- 当标题底边越过导航栏下沿后，原生导航标题淡入。
- 反向滚动时标题重新进入视野，导航标题淡出。
- 原生导航显示的是同标题的同步副本，不是将原 DOM 节点搬到导航栏。
- 因为正文标题始终按正常文档流滚动，所以不会留下任何占位空白。

建议由 JavaScript 使用 `IntersectionObserver` 监听标题哨兵：

```javascript
const sentinel = document.querySelector('[data-article-title]');
const observer = new IntersectionObserver(([entry]) => {
  window.webkit.messageHandlers.titleVisibility.postMessage({
    visible: entry.isIntersecting,
    title: sentinel.textContent.trim()
  });
}, { root: null, threshold: 0.05 });
observer.observe(sentinel);
```

## 4. 作者头像规则

- 有有效头像：正文保留真实头像，38×38pt；回答作者头像 26×26pt。
- 没有头像 URL：头像槽整体折叠，不保留空圆。
- URL 加载失败但有作者名：显示作者首字，仍占头像槽。
- 作者名也没有：仅显示来源信息，头像槽折叠。
- 不把 App 登录用户头像误用为文章作者头像。
- 导航栏不常驻作者头像，避免压缩标题；完整标题面板可复用 24pt 作者头像。

## 5. 图片与间距

| 关系 | 间距 |
|---|---:|
| 标题 → 作者 | 18pt |
| 作者 → 文武线 | 19pt |
| 文武线 → 正文 | 22pt |
| 段落 → 图片 | 22pt |
| 连续图片 | 14pt |
| 图片 → 图注 | 8pt |
| 图注 → 下一段 | 20pt |

图片规则：

- 使用原始宽高比，`width: 100%; height: auto; object-fit: contain`。
- 圆角收敛到 7pt；新闻图片也可使用 0pt 圆角，按来源风格决定。
- 不再对 `body > img:first-child` 强制限制为 96×96pt，因为它可能是真实正文图而非头像。
- 仅 `.avatar img`、`.author img`、`.source img` 应用头像尺寸。
- 图片加载中使用与实际 aspect ratio 一致的淡墨骨架；失败后在原位显示错误说明，不坍缩布局。

## 6. 链接、问答、引用和列表

### 正文

- 正文 17pt，行高约 1.82，段后 18pt。
- 动态字号直接修改 CSS 根字号，图片与边距保持视觉稳定。

### 问题标题

- 20pt 宋体加粗，行高 1.55。
- 上方 30pt、下方 13pt；第一条问题不增加额外顶部空白。

### 回答

- 2pt 淡墨竖线，左缩进 15pt。
- 回答作者头像 26pt；作者名使用靛蓝链接。
- 回答内容 16–17pt，不使用整块灰卡片。

### 链接

- 靛蓝文字 + 1pt 下划线，underline offset 3pt。
- 按下 100ms 出现靛蓝 10% 纸面底。
- 站内链接走 NavigationStack；外部 http(s) 使用安全浏览器；未知 scheme 拒绝。

### 引用

- 3pt 靛蓝左线，18pt 宋体；不添加大面积背景。

### 列表

- 使用原生项目符号，左缩进 22pt，条目间 8pt。

## 7. 图片交互

DOM 点击图片时应回传：

```json
{
  "src": "currentSrc 优先",
  "alt": "替代文字",
  "caption": "相邻 figcaption",
  "naturalWidth": 1200,
  "naturalHeight": 800
}
```

原生行为：

1. 点击：打开全屏图片浏览器，支持双击缩放、拖拽和单击关闭。
2. 长按：保存图片、复制、分享；保存前申请相册权限。
3. 加载失败：原位错误状态，提供重新加载图片。
4. VoiceOver：读取 alt；无 alt 时使用“正文图片，第 N 张”。

## 8. WebView 实现调整

当前是“外层 ScrollView + 禁止 WebView 滚动 + 动态高度”。建议改为：

- `webView.scrollView.isScrollEnabled = true`。
- WebView 直接占满详情页可用空间。
- 删除外层文章 ScrollView，阅读进度直接监听 `webView.scrollView.contentOffset`。
- 删除 `contentHeight` 状态和 `max(measuredHeight, 520)` 最小高度。
- 阅读位置恢复、返回顶部和进度百分比直接操作 WebView 的 scrollView。
- 图片加载和 DOM 变化不再导致 SwiftUI frame 反复更新，减少跳动与空白。

若短期不能重构为单一滚动容器，至少应：

1. 将最小高度从 520 改为接近实际内容的测量值。
2. 使用 `ResizeObserver` 在图片加载后重新回写高度。
3. 取消原生层固定封面，仅保留 HTML 内的图片。
4. 禁止用 opacity/transform 隐藏仍参与布局的标题。

## 9. 三种必须验证的正文类型

1. **编辑文章**：标题、作者、可选 hero、段落与正文图片。
2. **问答合集**：多个问题、多个回答作者、引用和连续图片；用户截图属于这一类。
3. **无作者 / 无图片**：折叠头像槽与媒体间距，标题后直接进入来源和正文。
