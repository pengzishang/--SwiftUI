修正后的页面结构

原生层只管导航与系统能力；所有文章内容由一个可滚动 WKWebView 连续承载。

原生导航返回 / 标题副本 / 操作
Web 标题自然滚走
作者署名有头像则保留
连续正文问答 / 链接 / 图片
系统浮层原图 / 浏览器 / 分享

1. 头像规则

  • 正文 HTML 有有效头像 URL：保留真实头像，38×38pt，圆形裁切并加 0.7pt 髮丝线。
  • 回答内部有头像：保留为 26×26pt，和回答作者链接同一基线。
  • 没有头像：整个头像槽折叠为 0，不留空白圆，也不生成虚构人物头像。
  • URL 失败：优先使用作者首字；连作者名都没有时仅保留来源文字。

2. 图片、标题与空白

18pt标题 → 作者
19pt作者 → 文武线
22pt段落 → 图片
14pt连续图片间距

不再单独渲染 `detailImageURL` 固定封面。若 API 确认图片是文章 hero，则把它注入同一 Web DOM，并放在标题之后或题图规范位置；问答型正文则完全尊重 HTML 图片顺序。

3. 为什么不会再留下“大截空白”

导航标题不是把 Web 标题搬到顶部，而是显示同一标题的第二份轻量副本。Web 标题仍在文档流中正常滚出视野，没有 opacity 隐藏、没有 translate 后残留的布局盒子，也没有原生头部和 WebView 之间的占位同步。

建议移除当前 `.frame(minHeight: htmlContentHeight)` 的 520pt 最小高度方案，改为让 WKWebView 自己成为唯一滚动容器。否则高度测量延迟和短正文仍会制造假空白。

5. 图片和链接的原生桥接

  • 图片点击：DOM 发送 `src/currentSrc/alt/caption`，原生打开全屏图片浏览器；加载失败在原位显示“图片暂不可用”。
  • 链接点击：DOM 先显示 100ms active 状态；原生判断站内、http(s)、未知 scheme。站内走 NavigationStack，外链用安全浏览器，未知 scheme 拒绝。
  • 长按图片：提供保存、复制、分享；保存前遵循相册权限。
  • 图片加载完成、字体变化、DOM 变化时，不再回写整个 WebView 高度；只更新阅读进度和导航标题阈值。

必须覆盖的三种正文状态

编辑文章

标题 + 作者 + 可选 hero + 段落。Hero 位于同一 Web 文档中，不在原生层重复。

问答合集

问题标题 + 回答作者 + 引用 + 多图连续流。当前截图属于这一类，应尊重 HTML 顺序。

无作者 / 无图片

折叠头像槽与媒体间距，标题后直接进入来源、文武线和正文，不保留占位高度。

交互提示：滚动正文观察标题自然交接；点击“保留头像”查看无头像时的布局收缩；点击正文图片查看原图反馈；支持字号与深浅色。
